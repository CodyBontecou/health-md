Chosen formats follow current product docs; no external fitness-service import compatibility is promised.
- [x] Workouts belong to the day their start time falls within the effective fetch calendar. Evidence: `HealthKitManager.swift` fetchWorkouts(for:), compatibilitySamplePredicate and ownsCompatibilitySample(startingAt:dayStart:dayEnd:). The range is start-of-day inclusive/end exclusive; returned workouts are filtered again by startDate. Exact UTC timestamps and calendar date labels serve distinct purposes.
- [x] CSV produces several Workouts rows per session, including type/sport marker timestamps but many five-field compatibility summary rows without Timestamp. Evidence: `CSVExporter.swift` Workouts block and `apps/apple/docs/reference/generated/core/summary-day.csv`, published producer-backed at `docs-src/public/reference/generated/core/summary-day.csv`. Two workouts of the same type reuse metric labels; no session UUID column is emitted there. Grouping only date/type is ambiguous. The guide directs per-session analysis to JSON rather than inventing a CSV session key.

- [x] JSON workouts array emits id/type/sport/startTimeISO/endTimeISO/duration/elapsedDuration, optional source/device metadata and available distance/statistics/laps/splits/routes/timeSeries. Producer uses source UUID when available, otherwise workout ID; the article recommends retaining exported IDs and inspecting duplicates rather than guaranteeing deduplication or equating distinct source IDs with distinct real-world activities.

A scalar distance cannot reconstruct coordinates. Missing routes/samples/statistics depend on available source data and authorized APIs; no universal complete-route guarantee.
