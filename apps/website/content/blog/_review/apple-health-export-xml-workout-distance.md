# Find workout distance in Apple Health export.xml — claim verification

Verified: 2026-11-19 by Claude (agent), method: mixed.

Executed: the published Python script was run (Python 3.14, stdlib only, `python3 -I`) against both published XML excerpts, a copy of the current excerpt with a full export version 17 DTD prepended, a malformed DTD, a repeated `startDate`, multi-activity/ambiguous workouts, and a generated 452 MB fictional export. `test/blog-workout-distance-recipe.test.mjs` re-runs the exact published script on the exact published XML and checks the printed output matches the article. Traced: format, deprecation and API claims to Apple developer documentation (read through developer.apple.com's documentation JSON on 2026-11-19), DTD copies published from real exports, and user reports labelled as reports.

Not done: no real Apple Health export was created or inspected for this article (none of the owner's or anyone's health data was used). XML shapes come from DTD copies taken from real exports plus Apple's documented API model. No device or app UI was exercised; the Health.md CTA is traced to producer fixtures and existing verified guides. All XML, values and output rows are fictional.

## Claims

- [x] Answer: current exports put workout distance in a `<WorkoutStatistics>` child (`type`, `sum`, `unit`); older exports use `totalDistance` / `totalDistanceUnit` on `<Workout>`. Evidence: export version 11 DTD (`<!-- HealthKit Export Version: 11 -->`) at https://github.com/AlekSi/applehealth/blob/main/healthkit11.dtd declares `<!ELEMENT Workout ((MetadataEntry|WorkoutEvent|WorkoutRoute)*)>` with `totalDistance`/`totalDistanceUnit` CDATA #IMPLIED. Export version 17 DTD copy at https://github.com/gauthier-se/verve/blob/main/internal/synthexport/prolog.txt declares `Workout` children `MetadataEntry|WorkoutEvent|WorkoutRoute|WorkoutStatistics|WorkoutActivity|WorkoutZoneGroup|Record`, keeps `totalDistance` #IMPLIED, and `WorkoutStatistics` EMPTY with `type`, `startDate`, `endDate` #REQUIRED and `average`, `minimum`, `maximum`, `sum`, `unit` #IMPLIED. That project's issue https://github.com/gauthier-se/verve/issues/138 reports a real version 17 export where no workout had `totalDistance` and totals were only in WorkoutStatistics; the article labels it a report.
- [x] `WorkoutStatistics` usage shape (type `HKQuantityTypeIdentifierDistanceWalkingRunning`, `sum`, `unit`, energy `unit="Cal"`, `workoutActivityType="HKWorkoutActivityTypeRunning"`, `durationUnit="min"`) matches the verbatim excerpt in the Developer Forums report https://developer.apple.com/forums/thread/714063 (values redacted there). Date format `yyyy-MM-dd HH:mm:ss Z` and `FileReference path="/workout-routes/route_….gpx"` match the version 17-derived fixture in the same verve repository. Excerpt values are invented.
- [x] Apple marks `HKWorkout.totalDistance` deprecated and points to `allStatistics` or `statistics(for:)`: https://developer.apple.com/documentation/healthkit/hkworkout/totaldistance (deprecationSummary). `allStatistics`, `statistics(for:)` and `HKWorkoutActivity` are iOS 16.0+: https://developer.apple.com/documentation/healthkit/hkworkout/allstatistics , https://developer.apple.com/documentation/healthkit/hkworkout/statistics(for:) , https://developer.apple.com/documentation/healthkit/hkworkoutactivity . The article doesn't name a deprecation version.
- [x] Sport → distance identifier table. Each identifier's Apple abstract describes its activity (walking/running, cycling, swimming, wheelchair, skiing/snowboarding, rowing, paddling, cross-country skiing, skating); rowing, paddle sports, cross-country skiing and skating sports identifiers are iOS 18.0+. Workout type constants (running, walking, hiking, cycling, swimming, wheelchairWalkPace, wheelchairRunPace, downhillSkiing, snowboarding, rowing, paddleSports, crossCountrySkiing, skatingSports, swimBikeRun "multisport activities like triathlons", traditionalStrengthTraining) checked under https://developer.apple.com/documentation/healthkit/hkworkoutactivitytype . The pairing is presented as following Apple's descriptions, not as an Apple-published mapping.
- [x] Export location: Health → picture/initials → Export All Health Data (https://support.apple.com/guide/iphone/share-your-health-data-iph5ede58c3d/ios, as already verified for the XML export guide). `export.xml` plus `workout-routes/` GPX linked via `WorkoutRoute` → `FileReference` per both DTDs. Inline DTD `<!DOCTYPE HealthData [` … `]>` per the version 17 copy.
- [x] Script behavior (executed): both excerpts print exactly the shown CSV; same run = 5.02 km from either shape; 12.4 mi → 19.956 km (12.4 × 1.609344 = 19.9559); strength workout distance fields blank, not 0; triathlon with swimming+cycling totals → blank distance, `ambiguous`, `Cycling+Swimming`; activity-only statistics are not promoted to totals; unknown unit keeps value with blank `distance_km`. Peak memory ≈32 MB (ru_maxrss) on a 452 MB fictional file with 2,000,000 records and 60,000 workouts. `removeprefix` requires Python 3.9+. `XMLPullParser` is documented in https://docs.python.org/3/library/xml.etree.elementtree.html#xml.etree.ElementTree.XMLPullParser alongside `iterparse`.
- [x] Unit strings `m` (SI prefixes such as `k`), `ft`, `yd`, `mi`: Apple HKUnit `init(from:)` tables, https://developer.apple.com/documentation/healthkit/hkunit/init(from:)-9qont . Conversion factors are the exact international definitions (mi 1609.344 m, yd 0.9144 m, ft 0.3048 m).
- [x] iOS 16 DTD/attribute problems are labelled user/developer reports. https://discussions.apple.com/thread/254202523 (Sept 2022, export version 12): malformed DTD and repeated `startDate` rejected by R, xmllint and a browser; several users said iOS 16.2 fixed it; one iOS 16.4.1 user still reported a DTD error. https://developer.apple.com/forums/thread/714063: second `startDate` where `endDate` belongs on WorkoutStatistics, Apple engineer asked for Feedback, no fix recorded.
- [x] Python's expat is non-validating (https://docs.python.org/3/library/pyexpat.html) yet, executed here, `ET.parse` failed with `syntax error` on a malformed ATTLIST and `duplicate attribute` on a repeated `startDate`; the script succeeds on both after dropping the DTD and renaming the repeated attribute. The malformed DTD is a synthetic reproduction, not Apple's original broken text.
- [x] Multi-activity: version 17 DTD `WorkoutActivity` attributes are `uuid`, `startDate` (#REQUIRED) and `endDate`, `duration`, `durationUnit` (#IMPLIED), children include `WorkoutStatistics`; no activity type attribute. Reading descendants would count leg statistics in addition to workout totals; the script reads direct children only (tested).
- [x] `sum` and `totalDistance` are #IMPLIED in the DTDs; missing distance is left blank. The workout-type examples (strength, yoga) are workouts that don't measure distance; no claim about how often real workouts lack distance.
- [x] Double counting: the Health app prioritizes overlapping sources instead of adding them (https://support.apple.com/108779: default priority manual → iPhone/iPad/Apple Watch → apps and devices, reorder under Data Sources & Access). The version 17 DTD comment states records that appear as children of a Workout also appear as top-level records. Raw record summing is presented only as a labelled approximation. Duplicate workouts from two sources are described as possible (each source writes its own workout), not as a frequency claim.
- [x] Routes are HKWorkoutRoute location samples: https://developer.apple.com/documentation/healthkit/hkworkoutroute . Laps/routes guidance defers to the existing verified workouts guide.
- [x] Health.md CTA: reads authorized Apple Health data on iPhone and writes daily CSV/JSON/Markdown to a chosen folder; does not import or read export.xml (existing verified claim in `_review/apple-health-xml-export.md`, `docs-src/src/content/docs/export.md`). Workout distance with explicit units: producer CSV `apps/apple/docs/reference/generated/core/summary-day.csv` row `2026-03-15,Workouts,Running Distance,10000,meters`; producer JSON `summary-day.json` workout `distance: 10000`, `distanceKm: 10`, `distanceMi: 6.2137…`. Offer: weekly, yearly and Lifetime access with a 7-day free trial on eligible subscriptions, per current `docs-src/src/content/docs/paywall.md` (which also states there is no local free-export allowance in this release, so the older "5 free export actions" wording on other posts is not repeated here). App Store URL: `verified-snippets.md`.
- [x] Privacy paragraph names the local folder workflow and describes the Cloud pilot as separate, opt-in, single-owner, intentionally uploaded API exports only, no public signup, no automatic device sync, not generally available — the same wording verified for the workouts guide (`privacy-policy.html`).
