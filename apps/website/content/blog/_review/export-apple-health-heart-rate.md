# Apple Health heart rate export claim verification

Verified: 2026-10-25 by Codex (agent), method: traced.

No device heart-rate export, sensor measurement, spreadsheet click-through, or visual QA was performed for this task. Claims are traced to producer source, generated fixtures, product/privacy docs and official Apple references. Website tests/build verify publication and links, not new health-data acquisition, continuous coverage or clinical interpretation.

## Claims

- [x] Heart picker names and categories follow `apps/apple/HealthMd/Shared/Models/HealthMetrics.swift`: heart_rate_avg/min/max, resting_heart_rate, walking_heart_rate and hrv. UI Minimum/Maximum map to CSV Min/Max labels. Metrics/detail/format selection, one-day Preview, writable destination and saved-file check follow `docs-src/src/content/docs/metrics.md`, `format.md`, `iphone-first-export.md` and `troubleshooting.md`. Five free actions/lifetime unlock: `paywall.md`; App Store URL: registry. Manual export needs no Mac. No native behavior or public contract changed.
- [x] `HealthKitManager.swift` fetchHeartData(for:includeDetailedTimeSeries:fetchScope:) requests general heartRate samples only when Detailed Time-Series is enabled and at least one heart_rate_avg/min/max is selected. Resting-only selection does not enter that branch. HRV samples require detail plus hrv. Resting/walking use most recent values within their day query, heart rate summaries use discrete statistics, and HRV summary uses an average of the SDNN type. The guide does not conflate those reducers.
- [x] Apple heart rate/resting rate and SDNN HRV are distinct types; bpm differs from milliseconds, and SDNN is not RMSSD. References checked 2026-10-25: https://developer.apple.com/documentation/healthkit/hkquantitytypeidentifier/heartratevariabilitysdnn and https://developer.apple.com/documentation/healthkit/hkquantitytypeidentifier/restingheartrate. Repo HealthMetrics identifiers and fetchHeartData corroborate the actual selected types. No health outcome or normative value range is asserted.
- [x] Source measurement availability varies with hardware/settings/context; export cannot create unrecorded readings. Apple's current https://support.apple.com/en-us/120277 describes model/settings-dependent measurements and limitations. The guide avoids asserting a universal fixed frequency, older background-only cadence, or complete continuous record. Permissions/native XML reference: https://support.apple.com/guide/iphone/share-your-health-data-iph5ede58c3d/ios.
- [x] Exact CSV names, units, values, sample timestamps and omitted summary Timestamp fields follow `CSVExporter.swift` Heart block and `apps/apple/docs/reference/generated/core/summary-day.csv`, published producer-backed at `docs-src/public/reference/generated/core/summary-day.csv`. Inline rows are exact source rows: Average Heart Rate 72.0 bpm, HRV 42.0 ms, Heart Rate Sample 61.0 bpm at 2026-03-15T00:30:00Z. Resting example is 58.0 bpm. Synthetic fixture covers serializers, not a complete day suitable for recomputing the independent summary queries.
- [x] CSV header/mixed Value/quoted fields/five-field compatibility rows follow reusable registry entry, source and `csv-row-contracts.md`. Exact Category/Metric/Unit filters isolate daily averages, resting values, samples and HRV. Workouts heart-rate statistics are a different category/context. Numeric conversion must occur after filtering; summaries and samples must not be concatenated as one measurement series.
- [x] JSON heart object field names and conditional arrays follow `JSONExporter.swift` Heart block and generated `summary-day.json`: averageHeartRate, heartRateMin/Max, restingHeartRate, walkingHeartRateAverage, hrv, heartRateSamples and hrvSamples. Sample entries have timestamp/value and optional metadata. Units/time_context are separate export metadata. Missing fields are not measured zero; compatibility arrays are not promised to expose original UUIDs/exact full source intervals.
- [x] Samples are assigned by startDate in the effective calendar's half-open day interval. Daily statistics deliberately use overlap-based query semantics. Evidence: `HealthKitManager.swift` ownsCompatibilitySample, compatibilitySamplePredicate, compatibilityStatisticsPredicate and fetchHeartData. Thus the exported sample rows need not independently reproduce every summary. UTC Z timestamps and date labels must be interpreted under time_context rather than simply slicing UTC strings into local dates.
- [x] Pooled-sample averages, daily-statistic averages and time-weighted averages are distinct calculations. The article requires explicit method and coverage counts, does not sum bpm as a meaningful total, and does not zero-fill/interpolate gaps without labeling. Duplicate export handling is explicit; equal timestamp/value pairs are not claimed to prove duplicate source records. A heart-rate bpm value is not an ECG waveform or beat-to-beat series. No diagnosis, causality or treatment claim.
- [x] Apple-only Lossless Health Records provides selected public API record UUIDs/provenance/intervals and capture diagnostics, not Apple's private database: `docs-src/src/content/docs/format.md`, `reference/canonical-healthkit-records.md` and generated field reference. Android guide is linked without assuming metric/reducer parity. No schema or cross-platform policy change.
- [x] Privacy/destination claims follow `privacy-policy.html` and reusable core/provider entries. Default folder export requires no Health.md account or server copy; external destinations govern their copies. Separate opt-in single-owner pilot retains only intentionally uploaded API exports, with no public signup or automatic device sync and no general availability. Public privacy checker explicitly covers new slug/revision. Detailed timestamps/source data are sensitive; no anonymity or deletion guarantees.
- [x] Existing blog generator supplies canonical/social/BlogPosting metadata, index and sitemap output. Export hub, CSV page and blog directory link to this guide. Setup/format/record reference/spreadsheet/workout/local-export/privacy/Android routes exist. Evidence: affected source, source-driven publication regression and full built-site checks.
