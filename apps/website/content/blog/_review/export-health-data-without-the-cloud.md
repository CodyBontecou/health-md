## Claims

- [x] Core manual iPhone folder export reads authorized HealthKit data, builds output on-device and writes to a chosen folder without a Health.md account or server copy by default. Evidence: `apps/apple/HealthMd/Shared/Managers/VaultManager.swift`, export renderers, `docs-src/src/content/docs/iphone-first-export.md`, `privacy-policy.html`, and `verified-snippets.md` core/account entries. API delivery is a separately selected target, not an intermediate step in this workflow. Source tracing, not new network evidence.
- [x] Local iPhone Folder target, folder control, one-day range, metric authorization, Preview and checking saved output follow `docs-src/src/content/docs/iphone-first-export.md` and `troubleshooting.md`. Preview is not described as proof of a successful write. Manual export needs no Mac. Five free actions, multiple days/formats per action and lifetime unlock follow `paywall.md`; App Store URL follows the registry. No native behavior or pricing changed.
- [x] Apple Files distinguishes On My iPhone from iCloud Drive and third-party providers: https://support.apple.com/en-us/102570, checked 2026-10-25. The guide directs a non-synced folder under On My iPhone and stops if that location cannot be selected. It does not infer a local boundary from the folder's name, a downloaded copy, or a note-vault label.
- [x] Sync and backup are separate. App data not synced through iCloud Drive can still be in iCloud Backup: https://support.apple.com/en-us/108770, checked 2026-10-25. The guide requires checking the owning app/location and device/computer backups rather than promising exclusion from every backup. Selecting a Health.md export folder does not reconfigure source Health/iCloud settings. No backup changes or destructive cleanup are performed or recommended as a universal fix.
- [x] Format choices, daily files, Summary, Detailed Time-Series and Apple-only Lossless Health Records follow `docs-src/src/content/docs/format.md`, generated format reference, `CSVExporter.swift` and `JSONExporter.swift`. CSV header, mixed-type Value and omitted final Timestamp are traced to `apps/apple/docs/reference/generated/core/summary-day.csv` and `csv-row-contracts.md`, with the reusable registry entry. Existing generated samples are linked, not modified.
- [x] Exported files can preserve sensitive timestamps, identifiers, provenance and selected detailed source content/attachments. No account does not imply anonymization. Evidence: `privacy-policy.html` source-data and destination sections plus producer lossless fixture/reference. The guide tells readers to protect files without making a security or anonymity guarantee.
- [x] Synced folders, desktop workbooks, vaults, uploads, recipients and backups can create additional copies under their own rules. Evidence: privacy destination/retention sections and existing Excel, Sheets, Obsidian and AI guides. Removing one file does not logically remove separately imported, backed-up, or derived copies; old exports are not relocated when a new destination is selected. Retention/deletion is explicitly destination-specific.
- [x] Separate opt-in single-owner Health.md Cloud pilot retains only API exports intentionally uploaded, with no public signup, no automatic device sync and no general availability. Evidence: `privacy-policy.html`, existing export/about disclosures, and reusable core/provider registry entries. Guide excludes that destination and is explicitly included in the public privacy checker and sitemap date audit.
- [x] Local health-data export is not a claim of no device/app networking. Purchase, scheduling, provider authorization and operational paths are separately described in `privacy-policy.html#operations` and the app operations docs. The guide links those boundaries and telemetry exclusions without a global offline, no-network, or no-retention promise. The engineering article remains the deeper reference.
- [x] Missing files/metrics are investigated through date, source records, selected metrics, folder availability and authorization, not treated as zeros or proof of a read-permission state. Evidence: `docs-src/src/content/docs/troubleshooting.md` and first-export docs. Android is linked to its own guide instead of applying Apple Files/HealthKit steps to it. No schema/platform policy changes or medical claims.
