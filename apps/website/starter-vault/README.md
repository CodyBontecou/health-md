# Health.md Obsidian starter vault

The source notes in `vault/` plus deterministic synthetic measurements in the builder produce a distributable vault. This is educational sample material, not a public export schema or a copied device dataset.

From `apps/website`:

```sh
npm run starter-vault:build
npm run starter-vault:check
node --test test/starter-vault.test.mjs
```

The download is `assets/downloads/healthmd-obsidian-starter.zip`. It has one root folder, `Health.md Starter`, with no community plugin code or auto-enabled plugins. The builder uses Node's built-ins and writes a deterministic, uncompressed ZIP with UTF-8 names, fixed timestamps, CRC checksums and ordinary file modes. Three SVG snapshots and the completed review are derived from the same day records. Fixed dates keep the sample from disappearing as time passes. No health export contract, producer fixture or plugin revision is changed.

`starter-vault:check` checks generated bytes against source without writing. The website build runs that check; after an intentional sample change, rebuild and commit the ZIP. The archive is copied through the existing `assets` static build path. Download discovery lives in the existing Obsidian workflow article.

To verify interactive compatibility against a checkout of the external plugin, use the optional test environment variable:

```sh
HEALTHMD_OBSIDIAN_PLUGIN_REPO=/path/to/health-md-visualizations \
  node --test test/starter-vault.test.mjs
```

This compiles and runs the external Markdown parser and metric resolver against every generated day; it does not modify or bundle the plugin. CI without that checkout still validates links, configuration, chart coverage, deterministic archive output, summaries and download discovery. The pinned source used for website visualization assets remains governed separately by `external-sources.json`.
