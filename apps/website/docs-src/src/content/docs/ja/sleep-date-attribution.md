火曜の朝に昨夜の睡眠を書き出すなら、通常は **昨日（月曜）** を選びます。Health.md の日次睡眠サマリーは現地時間の **12:00 から翌日の 12:00**、つまり月曜正午から火曜正午までを使います。活動データの午前0時の区切りとは異なります。

<div id="sleep-journal-window"></div>

## 昨日のノートに睡眠が入る理由

この期間では、就寝が午前0時を過ぎても通常の一晩をまとめて扱えます。開始の正午を含み、翌日の正午は含みません。睡眠が正午をまたぐ場合、隣接する日次サマリーにそれぞれ寄与することがあります。元のタイムスタンプをノートの日付に合わせて変更することはありません。

Apple と Android の互換サマリーはこの期間を共有しますが、指標、睡眠段階、元の記録、集計方法は異なる場合があります。起床日基準に切り替える設定はありません。

<div id="sleep-date-examples"></div>

## どの日付を選ぶか

以下は現地時間による架空の例で、実際の健康記録ではありません。

| 睡眠または活動 | 書き出す日付 |
| --- | --- |
| 月曜 23:45 から火曜 07:30 | **月曜** |
| 火曜 01:00 から火曜 07:30 | 火曜ではなく **月曜** |
| 火曜の昼寝 14:00 から 14:30 | **火曜** |
| 火曜の歩数と活動 | **火曜** |
| 月曜の夜の睡眠と火曜の活動 | **月曜と火曜** |

書き出しの現地タイムゾーンを確認してください。別のアプリが表示する起床日やファイルの更新日時で、ジャーナルの日付は決まりません。

## 期待したノートが空の場合

1. ジャーナルの日付と選択した睡眠指標を確認します。
2. 時計や元のアプリから Apple Health または Health Connect への同期を待ち、プレビューして同じ日を再度書き出します。
3. アクセスを確認します。iPhone の HealthKit では空の結果だけで読み取り拒否を判別できません。Android では元のアプリが対応する記録を Health Connect に書き込んだことを確認します。
4. 保存先と、書き込み・スキップ・失敗の結果を確認します。プレビューは保存の成功を証明しません。欠損はゼロではありません。

Daily Note Injection と API Endpoint のサマリーも同じ期間を使います。同期が遅れた場合は同じ日を再実行するか、スケジュールの遡及期間を確認してください。バックグラウンド実行は、指定時刻の保存成功を保証しません。

## サマリー、元の記録、セッションクエリ

生データや正規レコードは、元の時刻と独自の日付帰属ルールを保持します。日次合計からセッションを復元したり、元の区間を追加の睡眠として合算したりしないでください。

Apple の生データアーカイブは、元の記録の開始時刻に基づいて、現地の午前0時から翌午前0時までの日付に記録を割り当てます。一方、睡眠サマリーは正午から翌正午までの日誌の時間枠で区間を切り取ります。そのため、生の Sleep Analysis クエリが成功して朝の記録が含まれていても、その日付の睡眠サマリーは空の場合があります。サマリーの欠落を調べる前に、前の日誌日付をエクスポートし、`time_context.calendar_timezone` を確認してください。たとえば、9月22日 04:03〜11:52 UTC の記録は、UTC ではすべて9月21日のサマリーに属します。Europe/Lisbon では最後の52分が現地の正午より後になるため、その部分は9月22日のサマリーに加わります。

睡眠ステージの集計に明示的な `inBed` 記録は必要ありません。記録がない場合、Apple のサマリーは利用可能な、眠っている状態を示す各ステージの区間の和集合を使います。在床データがないときに在床時間を生成することはありません。サマリークエリの失敗は `diagnostics.partial_failures` に表示されるべきです。クエリが成功しても条件に合う区間がない場合は、データがないという正常な結果です。安静時心拍数は暦日ごとの別のクエリを使い、実際の安静時心拍数の測定を必要とします。睡眠ステージや読み取り許可だけでは、その測定値は得られません。

`healthmd_sleep_sessions` には対応する **Apple Health** の CLI/MCP 設定が必要です。Android の型付き MCP クエリは現在未対応です。[プラットフォーム機能](/ja/docs/guides/platform-features/)と [MCP](/ja/docs/mcp/)を確認してください。
