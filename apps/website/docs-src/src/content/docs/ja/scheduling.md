このページはiPhoneのスケジュールを説明します。Androidではバックグラウンド権限や購入条件が異なります。[Androidの自動化](/ja/docs/android/)を参照してください。

## 最初のスケジュール実行を確認する

1. 対象プロファイルを有効にし、指標、形式、データ詳細、書き込み方法、保存先を確認します。自動化の前に、完了した1日を手動で出力し、保存ファイルまたはエンドポイントの結果を確認します。
2. スケジュールから設定または管理を開きます。有効にして毎日・毎週・カスタムを選び、時刻と完了日1日分の対象範囲から始めます。ローカルの復旧通知が必要なら通知を許可します。
3. 有効状態、次回実行、前回の結果を確認します。実行後は履歴と実際の保存先を調べます。次回時刻や通知だけでは書き込み完了の証拠になりません。
4. 日付、単位、カバレッジ、欠損を確認します。ファイルが保存されても、元データの完全な取得が証明されるわけではありません。

Appleでは、1日以上を出力したスケジュール要求は手動などと共通の無料5回のエクスポート枠を使用します。Full Accessでこの共通制限を解除できます。[購入とロック解除](/ja/docs/paywall/)を参照してください。

## 完了日の対象範囲を理解する

毎日・毎週・カスタムには遡る日数を設定できます。カスタムは開始日からN日・週・月ごとに繰り返します。新しい実行ごとに、過去に出力した日も含め、設定した完了日の範囲全体を再出力します。3日なら昨日とその前の2日です。実行が遅れても、範囲は予定された実行日を基準にします。

今日の更新は当日分の別処理で、この範囲の代わりにはなりません。重複する出力ではパスと書き込み方法を確認し、同じ日のスナップショットを新しい測定値として加算しないでください。

## 正しい復旧方法を選ぶ

- **保留中のスケジュール復旧：** iPhoneのロックを解除してHealth.mdを開き、保留中の試行を確認します。未解決の日付、保存済み設定、保存先が保持されます。完了済みの日はそのままで、復旧時に範囲は拡大されません。
- **履歴から再試行：** 現在の設定と保存先でその範囲の新しい実行を開始し、新しい履歴行を作ります。実行前に現在の設定を確認してください。固定された保留要求の再開とは異なります。
- **保存先が変更・利用不能：** アクセスを回復するか、保留中のプロファイルを確認します。古いiPhoneのAPI復旧が変更後のエンドポイントや認証情報を黙って採用することはありません。元の試行が未解決のまま、新しい再試行を繰り返さないでください。

復旧、識別情報、保存先の規則は[エクスポートプロファイル](/ja/docs/export-profiles/)を参照してください。

## iOSが保証すること・しないこと

時刻は目標であり、完了時刻の保証ではありません。バックグラウンド実行はiOSが管理し、ロック中はHealthKitを読み取れない場合があります。バックグラウンド要求やサイレント通知でもこの保護は回避できません。

ローカル通知には権限が必要で、目標時刻の配信は保証されません。届いたらロックを解除して通知を開き、復旧を試みます。届かない場合はHealth.mdを開いて保留処理と履歴を確認してください。通知や経過時間で成功と判断せず、実際の結果を確認します。

## プロファイル別スケジュールとキャンセル

- 各プロファイルはカスタム間隔を含む独自のスケジュールを保持します。有効なプロファイルを変えても別のスケジュールは切り替わりません。
- 同じ保存先に同じ生成パスを書き込む可能性があるプロファイルには競合警告が表示されます。競合するスケジュールを有効にする前に確認してください。Health.mdがプロファイルを勝手に変更することはありません。
- 停止またはキャンセルは現在の試行だけを終了します。完了日を維持し、未解決日は再試行でき、スケジュールは有効なままです。
- 履歴の各行は、実行時のプロファイルと実際に使った保存先のプライバシー配慮済みラベルに固定されます。

固定設定と保存先は[エクスポートプロファイル](/ja/docs/export-profiles/)で管理します。
