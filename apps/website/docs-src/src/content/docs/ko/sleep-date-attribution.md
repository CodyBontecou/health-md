화요일 아침에 지난밤 수면을 내보내려면 보통 **어제인 월요일**을 선택합니다. Health.md의 일일 수면 요약은 현지 시간 **12:00부터 다음 날 12:00까지**, 즉 월요일 정오부터 화요일 정오까지를 사용합니다. 일반 활동 요약의 자정 경계와 다릅니다.

<div id="sleep-journal-window"></div>

## 수면이 어제 노트에 표시되는 이유

이 구간은 자정 이후에 잠들어도 일반적인 하룻밤을 함께 다룹니다. 시작 정오는 포함하고 다음 정오는 제외합니다. 수면이 정오를 넘으면 인접한 일일 요약에 각각 반영될 수 있습니다. 원본 타임스탬프를 노트 날짜에 맞춰 바꾸지는 않습니다.

Apple과 Android의 호환 요약은 이 구간을 공유하지만 지표, 수면 단계, 원본 기록과 집계는 다를 수 있습니다. 기상일 기준으로 요약을 옮기는 설정은 없습니다.

## 어떤 날짜를 내보내나요?

다음은 현지 시간의 가상 예시이며 실제 건강 기록이 아닙니다.

| 수면 또는 활동 | 내보낼 날짜 |
| --- | --- |
| 월요일 23:45부터 화요일 07:30 | **월요일** |
| 화요일 01:00부터 화요일 07:30 | 화요일이 아닌 **월요일** |
| 화요일 낮잠 14:00부터 14:30 | **화요일** |
| 화요일 걸음 수와 활동 | **화요일** |
| 월요일 밤 수면과 화요일 활동 | **월요일과 화요일** |

내보내기의 현지 시간대를 확인하세요. 다른 앱의 기상일이나 파일 수정 시간이 일지 날짜를 결정하지 않습니다.

## 예상한 노트가 비어 있다면

1. 일지 날짜와 선택한 수면 지표를 확인합니다.
2. 시계나 원본 앱이 Apple Health 또는 Health Connect와 동기화될 때까지 기다린 뒤 미리 보고 같은 날짜를 다시 내보냅니다.
3. 접근 권한을 확인합니다. iPhone의 빈 HealthKit 결과만으로 읽기 거부 여부를 알 수 없습니다. Android에서는 원본이 지원되는 기록을 Health Connect에 실제로 썼는지 확인합니다.
4. 저장 위치와 기록됨, 건너뜀, 실패 결과를 확인합니다. 미리 보기는 파일 저장 성공을 증명하지 않습니다. 누락은 0이 아닙니다.

Daily Note Injection과 API Endpoint 요약도 같은 구간을 따릅니다. 늦게 동기화된 데이터는 같은 날짜를 다시 내보내거나 일정의 과거 조회 기간을 확인하세요. 백그라운드 작업은 정확한 시각의 저장 성공을 보장하지 않습니다.

## 요약, 원본 기록과 세션 쿼리

원시 또는 정규 기록은 원본 시각과 자체 날짜 귀속 규칙을 유지합니다. 일일 합계에서 세션을 복원하거나 원본 구간을 추가 수면으로 합산하지 마세요.

`healthmd_sleep_sessions`는 지원되는 **Apple Health** CLI/MCP 설정이 필요합니다. Android 형식 지정 MCP 쿼리는 현재 지원되지 않습니다.[플랫폼 기능](/ko/docs/guides/platform-features/)과 [MCP](/ko/docs/mcp/)를 확인하세요.

[일정](/ko/docs/scheduling/), [문제 해결](/ko/docs/troubleshooting/), [형식](/ko/docs/format/) 안내도 참고하세요.
