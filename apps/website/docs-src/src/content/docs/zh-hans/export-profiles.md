---
title: "导出配置文件"
description: "将导出设置和目标位置一起保存，然后从 iPhone、Android、快捷指令、CLI、Tasker 或 adb 运行或计划这套配置。"
---

导出配置文件可将可重复使用的导出配置集中保存。请在 iPhone 或 Android 上的 Health.md 中管理它们。在 Apple 平台上，当前管理流程只在 iPhone 上有文档和测试；本文不声称 iPad 或 Mac 提供管理界面。

## 管理和编辑配置文件

打开**设置 → 导出配置文件**。列表会标记当前启用的配置文件，并允许你创建、重命名、复制、删除、启用或查看配置文件。打开详情页即可复制稳定 ID。最后一个配置文件无法删除。

“导出”标签页会编辑当前启用的配置文件。如果不想修改当前配置，请先启用另一个配置文件再更改导出设置。

每个配置文件都会固定重现一次运行所需的选择：

- 所选指标、数据详细程度、格式、模板、文件名、单位和写入行为；
- 平台支持时，可使用自己的目标文件夹和子文件夹、API 端点或已连接的 Mac 目标；
- 每日笔记、单项记录、汇总以及平台支持的其他输出选项。

计划任务会另行绑定到配置文件的稳定身份。切换当前启用的配置文件不会重定向该计划。配置文件运行会使用保存的快照，而不会借用另一个配置文件中已更改的设置。

## 安全运行和计划

- 每个配置文件都可以有自己的循环计划，包括应用提供的自定义周期。
- 平台权益仍然适用：Apple 免费额度可以包含计划操作，而 Android 计划功能需要一次性终身购买。
- 如果多个配置文件可能在同一目标写入相同的生成路径，Health.md 会发出警告。该警告不会悄悄更改配置文件或计划。
- 停止或取消只影响当前尝试。已完成的日期仍保持完成，未解决的日期仍可重试，循环计划也会保持启用。
- 如果引用的配置文件不存在，Health.md 会以安全方式失败，绝不会回退到当前配置文件或其他目标。

## 名称、稳定 ID 和自动化

显示名称面向用户，可以更改。稳定 ID 用于不受重命名影响的自动化。请从**设置 → 导出配置文件 → 配置文件 ID**复制。

- Apple 快捷指令按显示名称选择配置文件；配置文件参数为空时会使用当前启用的配置文件。
- Android 的 Tasker 和 adb 广播可以在 `PROFILE` extra 中提供稳定 ID 或名称。需要经受重命名的流程应优先使用 ID。
- Direct CLI 的受支持生成文件任务接受 `--profile PROFILE_ID`。配置文件提供固定的输出设置；必需的 `--destination` 仍用于选择电脑上已有的文件夹。

启用无人值守流程前，请先查看对应平台的自动化指南。

## 历史、恢复和隐私

配置文件感知的计划运行和自动化会在历史记录中保存运行时配置文件。历史还会保留实际目标的隐私安全标签。即使手动“导出”标签页运行使用当前配置文件的设置，也可能不会附加配置文件名称。之后重命名配置文件、更改目标或选择其他配置文件，都不会改写现有历史。

从导出历史启动的重试会使用当前配置的设置和目标，并以实际使用的信息创建新记录。它不会假称原配置文件控制了这次重试。相比之下，恢复或继续尚未解决的计划尝试会保留该尝试的确切日期、设置和目标。

配置文件和计划都是设备本地设置，不会在 iPhone、iPad、Mac 和 Android 之间同步。请在每台设备上重新创建所需配置，并在启用自动化前核对目标。
