本页描述iPhone调度。 Android有不同的后台权限和购买要求；请参阅 [Android 自动化](/zh-hans/docs/android/)。

## 验证第一个计划导出

1. 激活所需的配置文件。检查其指标、格式、数据详细信息、写入行为和目的地。手动运行一整天并在启用自动化之前检查保存的文件或端点结果。
2. 在 iPhone 上，打开**自动化**，选择一个自动化，然后轻点**计划**。在 Android 上，打开“计划”，然后选择“设置计划”或“管理计划”。启用计划，选择每天、每周或自定义，设置时间，并先从回顾已完成的一天开始。如需本地恢复提醒，请允许通知。
3. 检查调度是否启用、下一次发生和最后一次结果。尝试后，检查其历史详细信息和实际目的地；下次运行标签或通知并不能证明数据已写入。
4. 检查导出的日期、单位、覆盖范围和缺失数据。保存的文件本身并不能证明完整的源捕获。

在支持订阅的手机版本中，计划和手动导出需要有效试用、订阅、终身购买或保留永久访问权限。当地没有自由出口补贴。必须先恢复过期的访问权限，然后才能恢复挂起的工作。请参阅[解锁和付费专区](/zh-hans/docs/paywall/)。

## 了解全天窗口

每天、每周和自定义时间表都可以回顾。自定义节奏从开始日期起每 N 天、每 N 周或每 N 月重复一次。每个新事件都会重新导出整个配置的完成日窗口，包括之前导出的日期。三天回顾涵盖昨天和前两天；延迟执行使窗口固定在预定的火灾日。

今天刷新是单独的当日工作，而不是完整日窗口的替代品。在重叠导出之前检查路径和写入行为；不要将重复的每日快照添加在一起作为新的测量值。

## 选择正确的恢复路径

- **挂起的计划恢复：** 解锁iPhone ，打开Health.md并检查挂起的尝试。它保留其确切的未解决日期、保存的设置和目的地。已完成日期仍为已完成；复苏不会扩展到新的回顾。
- **从历史记录中重试：** 这将使用当前配置的设置和目标启动该范围的新运行，并记录新的历史记录行。按重试之前检查活动配置。它与恢复冻结的待处理尝试不同。
- **已更改或不可用的目标：** 恢复访问权限或在重试之前检查待处理的配置文件。旧的iPhone API 恢复不得默默地采用更改的端点或凭据。当原始尝试未解决时，请勿重复开始新的重试。

在 [导出配置文件](/zh-hans/docs/export-profiles/) 中查看待处理的恢复、配置文件身份和目标规则。

## iOS 保证什么和不保证什么

所选时间是目标，而不是保证完成时间。 iOS 控制后台运行时，锁定设备保护可以防止HealthKit读取。后台请求和静默唤醒通知不会绕过该保护。

本地恢复通知需要通知许可，并且不能保证在目标时间送达。如果您收到一个，请解锁设备并打开它，让Health.md尝试恢复。如果没有收到通知，请打开Health.md并检查待处理的工作和历史记录。验证结果而不是假设警报或经过时间就意味着成功。

## 配置文件时间表和取消

- 每个配置文件都可以保留自己的时间表，包括自定义节奏。切换活动配置文件不会重新定位另一个配置文件的日程安排。
- 当配置文件可以在同一目的地写入相同的渲染路径时，会出现冲突警告。在启用竞争计划之前检查它。 Health.md不会默默地更改任何一个配置文件。
- 停止或取消仅结束当前尝试。已完成的日期保持已完成状态，未解决的日期保持可重试状态，并且计划保持启用状态。
- 每个历史记录行仍然固定到运行时配置文件和实际使用的隐私安全目标标签。

在 [导出配置文件](/zh-hans/docs/export-profiles/) 中管理冻结设置和每个配置文件的目标。
