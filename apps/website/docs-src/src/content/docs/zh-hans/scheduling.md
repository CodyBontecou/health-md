本页介绍 iPhone 计划导出。Android 的后台权限和购买条件不同，请参阅 [Android 自动化](/zh-hans/docs/android/)。

## 验证首次计划导出

1. 激活目标配置文件，检查指标、格式、数据详细程度、写入方式和目标位置。启用自动化前，先手动导出一个完整日期，并检查已保存文件或端点结果。
2. 打开“计划”中的设置或管理，启用计划，选择每日、每周或自定义，设置时间，并从回溯一个完整日期开始。如需本地恢复提醒，请允许通知。
3. 检查启用状态、下次执行和上次结果。尝试后查看历史详情及实际目标位置；显示下次时间或收到通知并不能证明数据已写入。
4. 核对日期、单位、覆盖范围和缺失数据。保存成功本身不代表源数据已完整采集。

在 Apple 平台，导出至少一个日期的计划请求会与手动等导出共用五次免费操作额度。Full Access 可解除该共同限制。请参阅[解锁与购买](/zh-hans/docs/paywall/)。

## 理解完整日期窗口

每日、每周和自定义计划都可设置回溯范围。自定义计划从起始日期起每 N 天、周或月重复。每个新的执行时点都会重新导出整个完整日期窗口，包括此前已导出的日期。三天包括昨天及之前两天；即使延迟执行，窗口仍以原计划执行日为基准。

“今日刷新”是独立的当天任务，并不取代该窗口。导出范围重叠时检查路径和写入方式，不要把同一天的重复快照当作新测量相加。

## 选择正确的恢复方式

- **待处理的计划恢复：** 解锁 iPhone 并打开 Health.md，检查待处理尝试。它保留确切的未解决日期、已保存设置和目标。完成的日期保持完成；恢复不会扩大回溯范围。
- **从历史记录重试：** 使用当前设置和目标为该范围启动新执行，并创建新记录行。重试前检查当前配置。这不同于继续被冻结的待处理请求。
- **目标已改变或不可用：** 恢复访问或检查待处理配置文件。旧的 iPhone API 恢复不应悄悄采用已更改的端点或凭据。在原尝试尚未解决时，不要反复启动新的重试。

恢复、身份与目标规则见[导出配置文件](/zh-hans/docs/export-profiles/)。

## iOS 保证与不保证的事项

所选时间是目标，而非保证完成的时刻。iOS 控制后台运行，设备锁定可能阻止读取 HealthKit。后台请求和静默通知不能绕过该保护。

本地恢复通知需要权限，也不保证在目标时间送达。收到后请解锁设备并打开通知以尝试恢复。如果未收到，请打开 Health.md 查看待处理任务与历史记录。检查实际结果，不要仅凭提醒或经过的时间判断成功。

## 配置文件计划与取消

- 每个配置文件保留自己的计划，包括自定义周期；切换当前配置文件不会改变其他配置文件的计划目标。
- 如果多个配置文件可能在同一目标写入相同的生成路径，系统会显示冲突警告。启用相互竞争的计划前请先检查；Health.md 不会悄悄更改配置文件。
- 停止或取消只结束当前尝试。已完成日期会保留，未解决日期可重试，计划也保持启用。
- 每条历史记录都固定到运行时配置文件以及实际目的地的隐私安全标签。

请在[导出配置文件](/zh-hans/docs/export-profiles/)中管理冻结设置和配置文件目的地。
