# Google Drive export (Apple)

Google Drive is a profile-bound export destination. Health.md renders through the existing Apple v8 exporters, stages the exact generated bytes in protected no-backup storage, and sends them directly from the device to Google. Health.md has no token or health-data server.

## Google Cloud setup

Production and test builds must use separate Google Cloud projects. In each project:

1. Enable **Google Drive API** and **Google Picker API**.
2. Configure the OAuth consent screen and publish/verify it as required by Google.
3. Create a public iOS OAuth client. Do not create or ship a client secret.
4. Register the custom redirect URI and scheme supplied to the build.
5. Supply `GOOGLE_DRIVE_IOS_CLIENT_ID`, `GOOGLE_DRIVE_REDIRECT_URI`, and `GOOGLE_DRIVE_REDIRECT_SCHEME` as Xcode build settings. See `Config/GoogleDrive.example.xcconfig`.

A build with absent or placeholder values remains compilable and shows `configuration_missing`; it never falls back to Files, an API endpoint, a connected Mac, or another Google account.

Health.md requests only `https://www.googleapis.com/auth/drive.file`. Authorization uses `ASWebAuthenticationSession`, authorization-code PKCE S256, offline access, explicit consent, and Google's mobile folder Picker controls. Refresh tokens are stored in Keychain with after-first-unlock accessibility so scheduled work can refresh silently.

## Execution and recovery

- A destination binds Drive `user.permissionId` and immutable folder ID. Shared Drives are accepted only when exact metadata reports `capabilities.canAddChildren`; applicable requests set `supportsAllDrives=true` and include known resource keys.
- Profiles contain only the local destination UUID. Shared Setup, direct CLI/MCP, history, logs, and analytics do not receive account authority, Drive IDs, resource keys, tokens, upload sessions, paths, or rendered contents.
- Pending scheduled work freezes the local destination UUID and fingerprint. Reauthorization refreshes the same binding; another account fails with `account_mismatch`.
- Append, Markdown Update, and Daily Note injection download one exact baseline, persist it, run the existing merger once, and persist the complete final bytes before upload. A changed version/checksum, rename, move, trash, duplicate binding, or capability loss stops rather than force-replacing.
- Drive v3 has no documented compare-and-swap for `files.update`. Health.md performs complete-bundle preflight and exact-ID/version/checksum postflight, but a non-Health.md editor can still race the upload.
- Protected journals record generated IDs, final-byte hashes, resumable session state, and per-artifact checkpoints. Retry resumes the exact staged frontier. A partial multi-file commit is reported as `partial_completion`.
- Disconnect revokes when possible and always removes local credentials/authority. It does not delete remote files.

Scheduled authorization is silent only. If refresh is revoked, the journal remains and the operation reports `reauthorization_required`; foreground reconnect is required. There is no fallback destination.

## External release gates

Before release, complete production-shaped physical iPhone tests for Picker return, consent/reconsent, silent refresh while locked/after first unlock, Shared Drive/resource-key folders, revoked grants, session expiry, offline/rate limit/quota behavior, and conflicting edits. Complete Google OAuth publishing/verification, App Store privacy answers, reviewer instructions, and localized screenshots/copy. Tests in the repository use synthetic bytes and fake HTTP/Keychain services only.
