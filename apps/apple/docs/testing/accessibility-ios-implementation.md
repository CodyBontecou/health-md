# iOS accessibility implementation status

2026-09-08. **In progress; all five repair lanes merged, completed full matrix red, targeted corrections passed; clean-source full rerun pending.** The [September 7 audit](accessibility-ios-audit.md) remains unchanged historical evidence. Android's separately blocked 402-case device gate is not an Apple pass.

The shared outcome is full readable essential labels, explanations and values with operable native controls at the user's chosen text size. This repairs existing UI presentation; no settings/defaults, HealthKit semantics, contracts, schemas, metric identities/units, export bytes or Android implementation change.

## Verified foundation

- All 19 `Typography` entry points now use public SwiftUI relative-font resolution on iOS, with bundled OFL-licensed Geist faces. Base sizes/weights and mono figures are retained. This deliberately replaces fixed SF fonts; iOS 17 support does not rely on private SF names or the iOS-26-only `Font.scaled(by:)` API. Tests reject missing registered faces and prove view-scoped and live text-size growth.
- Active secondary/destructive button labels grow/wrap with at least 44pt minimum targets. Status labels and their symbols grow together. Full export filenames/messages wrap; status actions retain individual callbacks. Primary/Icon helpers are covered too, but they have no current app call sites and do not stand in for onboarding's separate buttons.
- Enabled status text uses readable named tokens. `successText` uses light green1000/dark green900; `errorText` uses red900; pending/disconnected text uses existing `textSecondary`. Semantic fills are unchanged. Both-theme tests include actual 10% tinted status surfaces and pressed/selected backgrounds.
- Shared macOS source retains native SF/SF Mono base sizes and desktop defaults. Hostless component tests avoid starting the production app's stores, cleanup and runtime services.

## Integrated repairs and central diagnostics

All five source-only lanes were merged serially after clean-head, ancestry and ownership checks. The integrated changes cover dialogs; format/frontmatter/template editing; metric/Settings/Sync reading; scheduling/export/profile controls; and onboarding/paywall. Their actual production components are registered in the isolated host. No lane's static checks were counted as runtime tests.

Central execution found issues that source parsing could not establish:

- A padded native switch label was not a physical row target. The production `A11ySwitchToggleStyle` now supplies one actual full-row action with native switch accessibility. Label-edge/thumb-side dispatch, unavailable state and the real isolated configuration-protection manager's block/unlock paths passed native UI tests.
- Compact date openers measured 34.5pt and did not respond to a padded-edge tap. The affected date/time controls now use native wheels with the original bindings/ranges, full wrapping readback and horizontal scrolling for narrow columns. Native wheel targets and value-preserving adjustments passed. A further fixture using the actual `ConfigurationProtectionManager.protecting(Binding)` proves native changed dates, rejected attempts, unlock, exact attempted/accepted writes and both date-range clamps. Page gestures use discovered reading content, not wheel columns or guessed screen-edge padding.
- UIKit Menu options measured 42pt and ignored minimum frames on SwiftUI action labels. `A11ySelectionMenu` retains native popover presentation but owns growing, scrolling >=44pt option Buttons. Native tests passed full date/time/unit choices, repeated current-option dispatch and independent hour/minute/period callbacks.
- The iOS dialog now has a real UIKit modal/escape boundary containing the production SwiftUI content and its complete live environment. Unit and native UI tests passed Escape dispatch, first-secondary cancellation before dismissal, initial field focus and Next/Done progression. This does not certify physical VoiceOver gestures.
- Test assumptions were corrected rather than reducing text or thresholds: native single-line newline rendering is compared against an actual native control while raw binding values remain unchanged; deliberately long fixtures exceed the 44pt minimum-height plateau; tight AX glyph bounds are not confused with allocated reading width; keyboard/wheel overscan is excluded from visible target measurements. One zero-test UI run was rejected, followed by explicit test enumeration and actual execution.

Updated actual-source hostless Mac result `integrated-mac-components-2.xcresult`: **6 passed, 0 failed/skipped**, including bounded shared dialogs, desktop 40pt action sizing, native font metrics, desktop dispatch policy and both-theme scrim alpha. Shipping result `integrated-app-build-2.xcresult` compiled the iOS app, full unit-test target and Mac dependency graph; it is **not hosted-suite execution**. ### Full-matrix findings and subsequent corrections

- `integrated-ui-matrix-1`: **49 total, 30 passed, 18 failed, 1 skipped**. Its Reduce Motion skip was rejected. No interrupted or zero-test bundle is accepted as completion.
- The scrim was genuinely transparent: the existing parser expects AARRGGBB, but its two tokens used RRGGBBAA. The failing both-theme regression established the defect; only those tokens were corrected to black alpha 112/255 and 179/255. Actual scrim cancellation and both-platform alpha tests passed.
- Dialog focus re-reveal now runs only while available height shrinks; doing it during every expanding interactive-dismissal frame fought the native gesture. The format keyboard toolbar now hosts an actual 44pt Button instead of a 36pt extracted native bar item.
- `integrated-current-matrix-2`: **103 total, 97 passed, 6 failed, 0 skipped**, exit 65, strict gate false, no stale sources. All 53 components, all 14 dialog UI cases and all 8 reading UI cases passed. Remaining failures involved format page/keyboard setup, a disabled Restore no-op, two native date page-reveal cases, and content under the pinned export footer. These partial successes do not make that run green.
- Failure screenshots/hierarchies led to stricter owner-aware tests: native List routes are scrolled before looking up virtualized links; reading text uses same-font full-width native references rather than a last-glyph width guess; RTL assertions preserve production bidi isolation. Page pans target actual reading content, retry genuinely stationary small gestures with bounded travel, and exclude known pinned footer geometry. Disabled no-op taps have a separate visibility contract; enabled-target requirements stay unchanged.
- `integrated-pan-and-obstruction-1`: **4/6 passed**, two failed, no skips. The subsequent `integrated-pan-and-keyboard-2`: **2/2 passed**, no skips, current-source gate true. The template test now types a synthetic draft, proves a visible software keyboard, and checks both unchanged raw text and unchanged binding setter count after actual interactive dismissal. An offscreen AX keyboard shell is not accepted as a visible keyboard. All six former failures have targeted green evidence, but these runs are not a unified final matrix.
- Real OS Reduce Motion was observed OFF then enabled through native Settings on the NEW owned simulator; `integrated-real-motion-and-date-1` passed its two runtime cases without skips. The full 103-case run also passed actual Reduce Motion. **Prior-state restoration and completion of its recorded roundtrip remain pending.** No defaults write or fake SwiftUI environment override supplied this evidence.

The shipping-host safety review found unsuppressed initialization, cleanup, defaults/keychain, recovery, analytics/StoreKit and reconnect paths. Neither shipping iOS nor macOS host was launched, and no runtime policy was rewritten to manufacture isolation. Synthetic callbacks do not prove HealthKit, purchase, scheduling, pairing, analytics, folder or history service journeys.
