# Health.md Pricing Analytics Worker

Cloudflare Worker + D1 ingestion endpoint for the Health.md pricing experiment.

This is intentionally **not** a UI. Data is queried with Wrangler/D1.

## Privacy contract

The worker stores only validated, coarse onboarding, pricing, and activation fields from Health.md on iOS, macOS, and Android:

- random pseudonymous app-install UUID generated by Health.md (`install_id`)
- event name
- experiment/variant IDs
- app version/build/platform
- paywall context
- coarse onboarding step and explicit Health/folder skip milestones
- free-export counts
- export target type (`local_file`, `connected_mac`, `api_endpoint`, or `preview_only`)
- coarse metric/date buckets
- allowlisted StoreKit or Google Play product ID (including Android `health_md_premium_lifetime`)
- purchase/restore outcome
- coarse authorization/error categories

Onboarding step values cover the seven-step iPhone flow, the macOS intro (`mac_how_it_works`, `mac_iphone_app`, `mac_connect`), and Android’s welcome/Health/folder/unlock/ready flow. Segment funnel reports by `platform`.

It rejects unknown envelope, event, and property fields and does **not** store raw
request IPs, user agents, request URLs, request headers, credentials, HealthKit
values, metric names, health dates, vault/folder/file paths, peer device names,
user text, or exported content. It is collected automatically and is not used for
advertising or cross-app tracking. Apple builds explain the strict exclusions under
**Settings → Privacy & Analytics**; Android discloses its bounded, non-disableable
collection during onboarding and in its Health Connect rationale. The full privacy
policy covers both.

Validated event rows are automatically deleted after 13 months by the daily
scheduled handler configured in `wrangler.toml`. Cloudflare necessarily processes
ordinary connection information under its own terms. Before deployment, verify
that Worker invocation logs/Logpush do not retain request bodies, raw IPs, or
headers beyond the intended provider-level minimum.

## Setup

```bash
cd worker/pricing-analytics
npm install

# Create the D1 database once.
npm run db:create

# Copy the returned database_id into wrangler.toml.

# Apply schema locally or remotely.
npm run db:migrate:local
npm run db:migrate:remote

# Deploying also installs the daily 13-month retention cron from wrangler.toml.

# Optional abuse-throttling key for deployed ingestion.
wrangler secret put INGEST_TOKEN

npm run deploy
```

Deployed production endpoint:

```text
https://health-md-pricing-analytics.costream.workers.dev
```

The app has this endpoint as its release fallback. You can override it per build
with:

```bash
PRICING_ANALYTICS_ENDPOINT_URL=https://health-md-pricing-analytics.costream.workers.dev
PRICING_ANALYTICS_INGEST_TOKEN=<same token as INGEST_TOKEN, if configured>
```

`INGEST_TOKEN` is currently unset on the Worker so the production app does not
need to embed a shared token. If an ingest token is configured later, set the same
value as a release build setting; treat it as an abuse-throttling key, not a true
secret or a privacy boundary, because mobile app bundle values are extractable.

## Wrangler queries

Recent events:

```bash
wrangler d1 execute health-md-pricing-analytics --remote --command \
"SELECT received_at,event_name,variant_id,platform,paywall_context,purchase_outcome
 FROM pricing_events
 ORDER BY received_at DESC
 LIMIT 20;"
```

Distinct-install onboarding funnel by platform, app version, and experiment variant for starts from the last 30 days that are at least 24 hours old:

```bash
npm run query:onboarding
```

The report includes a seven-day-mature purchase denominator plus activated/not-activated free-choice cohorts. Activation and purchase conversion are populated only for builds that emit `pricing_export_succeeded` and `pricing_purchase_finished`; Android currently contributes onboarding and purchase-tap milestones, not export or purchase lifecycle outcomes. Activation and purchase windows use Worker receipt times because clients intentionally do not send raw event timestamps, so delayed offline delivery can blur either boundary. Activated/not-activated purchase differences are descriptive correlations, not causal estimates.

Pricing funnel by variant:

```bash
wrangler d1 execute health-md-pricing-analytics --remote --command \
"SELECT
   variant_id,
   COUNT(DISTINCT CASE WHEN event_name IN ('pricing_export_preview_generated','pricing_export_succeeded') THEN install_id END) AS activated_users,
   COUNT(DISTINCT CASE WHEN event_name='pricing_paywall_shown' THEN install_id END) AS paywall_users,
   SUM(CASE WHEN event_name='pricing_paywall_shown' THEN 1 ELSE 0 END) AS paywall_views,
   COUNT(DISTINCT CASE WHEN event_name='pricing_purchase_started' THEN install_id END) AS purchase_starters,
   COUNT(DISTINCT CASE WHEN event_name='pricing_purchase_finished' AND purchase_outcome='succeeded' THEN install_id END) AS successful_purchasers
 FROM pricing_events
 GROUP BY variant_id
 ORDER BY variant_id;"
```

Windowed funnel read:

```bash
wrangler d1 execute health-md-pricing-analytics --remote --command \
"SELECT
   variant_id,
   COUNT(DISTINCT CASE WHEN event_name IN ('pricing_export_preview_generated','pricing_export_succeeded') THEN install_id END) AS activated_users,
   COUNT(DISTINCT CASE WHEN event_name='pricing_paywall_shown' THEN install_id END) AS paywall_users,
   SUM(CASE WHEN event_name='pricing_paywall_shown' THEN 1 ELSE 0 END) AS paywall_views,
   COUNT(DISTINCT CASE WHEN event_name='pricing_purchase_finished' AND purchase_outcome='succeeded' THEN install_id END) AS successful_purchasers
 FROM pricing_events
 WHERE received_at >= '2026-05-18T00:00:00Z'
   AND received_at <  '2026-06-01T00:00:00Z'
 GROUP BY variant_id;"
```

Use distinct-install columns for funnel conversion; raw view/event counts measure frequency and can exceed the number of people in a stage.

Revenue still comes from App Store Connect. Join the D1 activation/paywall counts
with ASC proceeds/refunds in the experiment runbook to compute:

```text
net revenue per activated user = (ASC proceeds - refunds) / activated_users
```
