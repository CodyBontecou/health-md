# Isolated native accessibility components

This separate test app has no Health.md app bootstrap, HealthKit, StoreKit, vault, scheduler, analytics or transport dependencies. The real configuration-protection manager uses a uniquely named synthetic defaults suite. It is not a fake implementation: the generator compiles production sources directly, and generates only the status-prefix and Status/ConfigurationProtection identifier excerpts from current production bytes with source spans and SHA-256 provenance. No configuration-protection stand-in is provided.

```sh
# From the repository root; XcodeGen must be installed.
python3 apps/apple/scripts/generate-a11y-test-project.py apps/apple/build/a11y-owned
# Create/record a NEW simulator; substitute its explicit UDID below. Never use booted.
xcodebuild test -project apps/apple/build/a11y-owned/HealthMdA11y.xcodeproj \
  -scheme HealthMd-A11y-iOS -destination 'platform=iOS Simulator,id=<OWNED_UDID>' \
  -derivedDataPath apps/apple/build/a11y-owned/dd \
  -resultBundlePath apps/apple/build/a11y-owned/result.xcresult \
  -parallel-testing-enabled NO -collect-test-diagnostics never \
  CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO CODE_SIGN_IDENTITY='' DEVELOPMENT_TEAM=''
```

The macOS scheme `HealthMd-A11y-macOS` runs hostless XCTest against a framework compiled from the actual shared design system and Geist dialog sources. It does not start the production Mac host, which initializes destination stores, cleanup and runtime services. Use a separate derived-data/result path. This is an isolated equivalent, not a full-host macOS test pass.

## Component and lane contract

- Existing `Typography` signatures remain. On iOS they use bundled registered Geist faces and native `Font.custom(_:size:relativeTo:)`; no private SF names, fixed point-size resolution or process-global UIFontMetrics. `Typography.scaled(size:weight:relativeTo:monospaced:)` is available for existing bespoke base sizes. On macOS it keeps the existing native system sizes/weights/design.
- Readable tokens: `Color.textSecondary` for enabled helper copy; `Color.successText` is light green1000/dark green900 and `Color.errorText` is red900. Existing success/error fills are unchanged. Pending/disconnected pill text uses `textSecondary`. `textMuted` is not an enabled-copy token.
- `HealthMdTests/Support/A11yHosting.swift`: `@MainActor A11yHosting(view, size:)`, `measured(proposal:)`, `update(view)`, `capture()`, `close()`. It hosts real views in UIKit, disables inherited safe areas for embedded probes, and remeasures/layouts after attachment. Always close hosts. Do not use ImageRenderer to infer native-menu failures.
- `AccessibilityTests/UITests/A11yUITestSupport.swift`: inherit `A11yUITestCase`; `launchScenario(_:size:theme:locale:width:height:)` launches this synthetic app, not the shipping app. Supported sizes: `large`, `xxxLarge`, `accessibility1`, `accessibility5`. `reveal(_:in:)`, `tapEdge(_:in:)`, `saveScreenshot(_:name:)` are available. The scroll helper checks actual scroll viewport bounds, not just window bounds. Native modal/keyboard tests must use their own real owner/window geometry where appropriate. `above:` excludes a known pinned obstruction; `tapDisabledEdge` explicitly tests a visible disabled no-op without relaxing enabled-target hittability.
- `A11yScenarioContainer` applies the requested text environment, theme, locale/RTL, and optional constrained viewport. Constraints are synthetic remaining space, not physical Display Zoom or every IME. The OS keyboard still requires a real focus/type/dismiss test.
- New scenarios belong in uniquely named `AccessibilityTests/Scenarios/<Lane>A11yScenario.swift`, assembling production components with synthetic state/callback counters only. Registered routes are `foundation`, `dialogs`, `format`, `reading`, `scheduling` and `onboarding`; source lists are explicit in the generator. Unit tests can go in uniquely named `HealthMdTests/Views/<Lane>A11yTests.swift` with `#if os(iOS)` and `@testable import HealthMd`; these synchronized test groups need no lane pbxproj edit. Native isolated UI tests go in `AccessibilityTests/UITests/<Lane>A11yUITests.swift`.
- Private production components may be extracted into uniquely named, correctly platform-guarded production files and used by BOTH real views and tests. Never hand-copy an implementation into tests, replace real guards with stubs, or call synthetic counters proof of purchases/HealthKit/storage.

## Integrated native-control details

- `A11ySwitchToggleStyle` gives the growing row one real physical action and preserves native switch accessibility through SwiftUI's public accessibility representation. Its decorative switch cannot dispatch another tap. Component UI tests assert one switch, exact label-side/thumb-side callbacks, and actual production protection rejection/unlocking.
- `A11ySelectionMenu` uses a native popover with scrolling native SwiftUI Buttons. iOS 26.5 UIKit Menu rows measured 42pt and ignored minimum frames on action labels. The popover owns genuine >=44pt, growing option targets; its geometry is independent of the underlying page. Existing same-option callback policies remain in the callers.
- Scheduling date/time controls use native wheels: the compact opener measured 34.5pt, and a padded-edge tap did not open it. Callers retain their exact date bindings/ranges and full wrapping readback. Narrow columns scroll horizontally. Page gestures use discovered reading content, not wheel columns or a guessed screen-edge gutter. Native wheel AX overscan is not treated as visible target area. The guarded-date scenario uses the real production binding guard and proves accepted/blocked native changes, unlock, exact attempted/accepted writes, and both range limits.
- The iOS Geist card has a real UIKit modal boundary with a public `accessibilityPerformEscape` implementation, hosting the actual SwiftUI content and its complete live environment. Unit/native UI tests dispatch that action and verify first-secondary cancellation before dismissal. This is not a physical VoiceOver gesture test. macOS retains its existing native Escape/Return behavior and 40pt desktop action minimum.
- `ReadingConnectionEntry` routes its full styled editor tap region through the caller's explicit `focusEditor` callback. Padding alone did not focus the real editor. Existing Manual IP focus/dismissal stays caller-owned; CLI fields have separate UI-only focus state. Native tests tap the actual top-padded host/port edges and type through the application's current responder (not a named field that could refocus itself), checking independent exact values and connection callbacks.
- `keyboardKey(_:in:)` handles native key capitalization and only the known first-run keyboard tutorial. Keyboard target checks use the actual owner window and visible hit region; iOS 26.5 bottom-row AX slop extends below the SE screen. Interactive-dismissal tests first prove a visible software keyboard and retain draft/callback evidence. A native AX keyboard can persist entirely below its window after dismissal; existence alone is not visibility.
- `reveal` resolves scroll/collection/table ancestry and allocated scenario geometry, excluding keyboard/navigation chrome and explicit pinned footers. Reading-content pan anchors avoid nested editors/date controls and clipped glyphs beside system chrome; repeated drags on a reported y34.5 text edge were observed to move nothing. Small stalled pans get bounded additional travel instead of a fixed stride that overshoots tall controls. Growing controls taller than the viewport require their real leading 44pt plus separate complete-copy/end-to-end reading coverage. Offer-price captures use settled pans, verify at least 44pt overlap between slices, and require the actual trailing 44pt inside the reading viewport before its physical edge tap; a fling past the price is not successful reading.
- The scrim uses the existing AARRGGBB parser's black-alpha tokens on both platforms. Native tests verify the documented alpha, actual outside-card cancellation, and dialog focus re-reveal only when keyboard space shrinks (not while interactive dismissal expands it).
- Always check actual discovered/executed test counts, failures, skips and current-source hashes. A zero-test `xcodebuild` exit 0 is not a pass. Runtime Reduce Motion requires the real setting, never assignment to the read-only SwiftUI environment value.

Foundation coverage includes all 19 entry points plus five native positive controls at four text sizes, base metrics/registered faces/weights, live environment changes, monospacing, production status/symbol growth, minimum targets and actual edge callbacks, both-theme/tinted contrast, and eight native simulator renders. Integrated screen components, native popovers/dialogs/keyboard and the isolated real protection manager have separate suites. Shipping-host journeys and full-screen matrix completion must be established from their own current-source execution receipts. Human VoiceOver, physical Display Zoom/IME and reading pace remain manual gates.
