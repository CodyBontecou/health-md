# Wear screenshots

`wear-app.png` and `wear-tile.png` must be manually captured from the exact release build at 400×400 or larger. Use app UI only: no frame, marketing copy, background, mask, or production health values. `scripts/capture-wear-play-screenshot.sh` captures an unmodified physical-watch framebuffer only after verifying the exact expected Wear version code, installed Wear base APK digest, authorized Play App Signing certificate SHA-256, explicit operator confirmations, and an independent `REVIEWER_ID`/`REVIEW_TICKET` approval record; for `tile`, first open the system-hosted installed Tile, never the picker preview. Release is blocked until both pass `scripts/validate-wear-play-assets.py` and visual review. Package the generated-APK and screenshot-capture evidence into a protected submission, then dispatch `.github/workflows/android-wear-screenshots.yml` from the exact annotated release tag with its exact submission run ID and attempt. The workflow supplies the protected reviewer/ticket and QA-only Play account to `sync-google-play-wear-screenshots.sh`, retains non-overwritable attempt-qualified committed-edit evidence, and protected ingest injects that receipt rather than accepting a submitter-supplied copy. Production promotion independently compares Play's current two screenshot hashes with the sealed approved PNGs before changing either track.
