# Android release lanes

`validate_wear_release` builds and validates both AABs without publication. The legacy Fastlane upload lanes are not used for Wear publication because Supply models one default track and cannot assign the phone and Wear bundles to distinct form-factor tracks. The protected release workflow uses `scripts/upload-google-play-paired-release.sh` to upload both bundles in one edit while assigning phone to `qa` and Wear to `wear:qa`. Exact-release Wear screenshots are captured from the later Play-generated closed-track installation and replaced only by protected `.github/workflows/android-wear-screenshots.yml`, which invokes the evidence-bound implementation script; requiring them during initial upload would be circular. Production promotion similarly updates `production` and `wear:production` in one edit. Run credentialed mutation only from protected workflows after approval.
