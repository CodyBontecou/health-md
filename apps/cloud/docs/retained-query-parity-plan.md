# CLI/MCP query convergence for retained exports (proposal, not shipped)

**User outcome:** A user or agent can ask the same factual question about available health data through the direct CLI/MCP and the hosted MCP reader, with explicit evidence, units, provenance, coverage and missingness. The hosted reader is **not** a live-device bridge: it may answer only from original retained API-export envelopes. No new mobile capture or additional cloud upload is authorized by this proposal.

The standalone CLI's portable MCP calls a foreground paired iPhone using the direct query v3 protocol. Its typed operations include `healthmd_metric_chart`, `healthmd_sleep_sessions`, `healthmd_workouts`, `healthmd_coverage`, `healthmd_compare_periods`, `healthmd_training_alignment`, `healthmd_training_evidence`, `healthmd_query`, and `healthmd_evidence_packet`; export/pairing/job tools have side effects and are not hosted-query candidates. The current hosted reader instead has six Apple-v8 daily aggregate tools and five full-export JSON discovery/navigation/byte tools. These are **not** equivalent datasets or interchangeable response contracts.

| Direct capability | Retained cloud evidence | Next safe step |
| --- | --- | --- |
| Metric catalog and daily charts | Verified Apple v8 daily aggregates, retained export IDs/dates | Share canonical registry IDs and bounded daily query receipt shape; omit unsynced and unsupported values. Keep Apple/Android distinctions. |
| Sleep sessions, workouts and fine-grained evidence | Only if optional source archives/typed sections are present in uploaded JSON | Inspect both platform schemas and fixtures; add documented versioned adapters only for proven fields, with exact export/pointer evidence. Never project aggregate sleep duration into a fabricated session. |
| Coverage and period comparison | Uploaded days and capture-state fields, incomplete device history | Report uploaded/captured/missing dates distinctly; no assumed zeros or inferred lifetime coverage. Reuse reducer semantics only where exact. |
| Raw artifacts, file exports, status, pairing, resume/cancel | Direct iPhone and client spool, not accepted by this receiver | Keep unavailable on hosted MCP. Android Raw API Snapshot artifacts are not ingested here. |

Before exposing a shared `healthmd_*` tool name, define one language-neutral request/receipt contract under `packages/contracts` with an explicit `source: direct_device | retained_api_export` and capability/missingness fields; use the same exact semantics in Rust CLI/MCP and the cloud adapter or keep names distinct. Review Apple, Android, CLI, shared-core, website and external consumer fixtures, follow the export schema/version policy, and run all affected gates. Existing `full_export` credentials remain able to traverse every currently retained envelope via the five bounded discovery/navigation/byte tools, so the absence of a typed adapter does **not** hide already uploaded data. No parity claim or additional read credential is implied by this plan.
