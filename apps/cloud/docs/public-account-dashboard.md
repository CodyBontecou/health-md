# Owner-only public account dashboard — deployment contract

`https://healthmd.app/dashboard` is a **temporary redirect** to `https://account.healthmd.app/dashboard`. The static Vercel website must never proxy browser cookies, credentials, exports, or account API requests; its third-party scripts do not run on the isolated account hostname. The same-origin account dashboard has no third-party assets or analytics, uses a strict CSP and a Secure, HttpOnly, SameSite=Strict host-only session cookie. The owner explicitly accepted username/password without MFA for this unbacked single-user pilot; public signup, OAuth, password recovery, and other users are **not** enabled. Do not present this as a general production launch.

**Multi-user source milestone (not live):** the split account Worker now exposes account-owned browser-session inventory/revocation; migration `0016_magic_link_session_claims.sql` atomically binds each winning one-time-link claim to its session/audit creation, and issuance, logout, individual revocation and revoke-others each use atomic operation-specific audit markers to reconcile lost D1 responses, and an unreadable revocation never claims success or clears a current cookie. It also exposes a 50-entry reviewed security-activity history containing only event types/timestamps, and accepts account deletion only after password reauthentication or an email-link session created within the prior 15 minutes. Disabling the account immediately invalidates session, ingest, and MCP authorization. A durable D1 deletion row is sent to the isolated lifecycle Queue when configured; the scheduled maintenance scan remains a recovery fallback. The consumer removes bounded export and active-intent ciphertext batches before metadata/account completion and never logs identifiers or payloads. The browser creates one high-entropy opaque `hmd_del_…` status receipt before submitting the destructive mutation; the service stores only its SHA-256 hash, keeps the internal deletion job ID in D1/Queue, and exposes a no-session status checker that returns only pending/completed until the bounded receipt expiry. Because the caller knows the receipt before D1 commit, a lost response cannot strand a disabled account without status authority. Forward-only migration `0015_deletion_receipt_authorities.sql` attaches independently hashed concurrent/exact-retry receipts to one internal account job, so one accepted browser request never invalidates another caller's pre-generated authority. The handler reconciles the durable deletion-job/receipt postcondition after an ambiguous batch response; because account disablement, unique-job creation and receipt attachment are one D1 transaction, it does not require the user row to survive a concurrent maintenance completion. If that read is unavailable, it returns retryable backpressure without undoing the job, clears the authenticated dashboard, and keeps the receipt visible. Maintenance likewise commits final disabled-user erasure and the completion marker atomically, verifies their exact durable state after lost responses, and retries idempotently when the read is unavailable. The credential stays in memory/manual copy, never a URL or browser storage; an expired credential is cleared without dropping an unfinished deletion job. Event target IDs never leave the server; this history is not an out-of-band security notification. The placeholder Queue, Worker profiles, and production identity mode are not deployed.

The public administration listener runs on loopback **18791**, behind its own nginx loopback proxy **18792**, Tunnel identity, hostname and DNS record. It uses the writer's account database and encrypted-object keys; it is **not** a separately privileged reader like MCP. Its adapter's positive route/method list excludes `POST /api/v1/exports`, signup, raw files, arbitrary paths and MCP. The iPhone writer remains tailnet-only on **18788** and synthetic preview remains upload-disabled on **18787**; do not change the unrelated port 443 route. The MCP reader keeps its distinct read-only OS identity, credentials and public `mcp.healthmd.app` ingress. Reuse neither the MCP Tunnel credential nor its service-account secrets for administration.

The owner may list/download stored exports, page older export and day metadata, export account data as bounded uncompressed TAR pages, view bounded retained-summary charts, manage write-only upload tokens, sign out, request account deletion after password re-entry, and create/revoke per-agent read tokens. All account-side retained-object readers reject ciphertext whose exact container size does not match bounded metadata before materializing the R2 body. Each portability archive contains a manifest plus at most five owner-scoped, hash-verified exact envelopes, streams after authentication, and never stages a plaintext archive in storage. Issuance requires password re-entry and explicit full-export consent for that named agent; its serialized transaction caps the owner at ten active grants and couples the reviewed audit event, and the one-time plaintext is released only after exact durable token/audit read-back, including after a lost D1 response. New tokens last 1–90 days, are returned only once and cannot be recovered; if verification itself is unavailable, the owner must review/revoke the redacted inventory before retrying. Revocation is owner-idempotent and reports success only from exact durable revoked/audited state, without relying on adapter change counts. The reader enforces account scope and revocation at every request. **Existing aggregate-only Muse credentials remain aggregate-only**; no rotation or Grokbot credential is implied. The owner must review the specific provider's retention and handling before copying a credential into its secure store. Do not paste tokens into prompts, URL parameters, chat, logs or tickets. This is still an unbacked pilot: VM/disk/key loss can erase everything permanently. Uploads are limited by quota; unlimited revision retention means time, not space or recoverability.

**Dashboard visualization v1 (owner session only):** `GET /api/dashboard/trends` returns at most 30 calendar days ending on the latest current daily snapshot. It verifies and decrypts only selected current Apple-v8 compatibility envelopes, projects Steps, Total Sleep (seconds to hours), and Resting Heart Rate using the shared metric registry's exact units, and returns null for absent or unverified values; zero is not missing. Android v4/v5, provider data, archive data, prior revisions, absent days, and unsupported units are never silently presented as Apple readings. Unsupported profiles and an exhausted 48 MiB per-request read budget are labeled, not filled in. No new data is stored, no export schema or direct protocol changes, and nothing here queries a live phone or grants a write/read token additional authority. The owner-only response is no-store and uses the existing host-only session. The dashboard uses a `shadcn dashboard-01`-inspired inset workspace, responsive sidebar, four summary cards, one metric-selectable area chart, and tabbed tables for daily summaries, current snapshots, and original export history. The three metric cards show the latest observed value in the selected window and an absolute, unit-bearing change against the previous observed day, explicitly dated; this is not a period-over-period percentage or clinical trend judgment. The 7/14/30-calendar-day controls slice the same bounded response, ending on the latest retained day, not today. Each chart area is filled only within contiguous verified observations; isolated values and measured zeros remain visible. Daily summaries support owner-date/evidence filtering, numeric/date sorting (unavailable values always last), column visibility, and 10/20/30-row pagination. These controls stay in page memory, never URLs or browser storage. Keyboard tab navigation, point inspection, original downloads, archive paging, and inline non-launchable planner selections remain available. All light/dark components are first-party CSS/SVG with no external chart SDK, font, shadcn CDN, or telemetry; no React/Tailwind migration, endpoint expansion, or mobile contract change is required. `GET /api/exports` additionally returns `storage.dayCount` so the overview counts **all** current snapshots, not only its first 50 paginated rows.

**Shared account workspace:** overview, trends, export history, connections, and account/security are dedicated central views inside the same sidebar shell, rather than anchor jumps down a long dashboard. Explorer uses the same tokens, controls, cards, and table system with keyboard-accessible Compare summaries / Export library / Original fields tabs. `/repair` and `/login` also use that shell; signed-out pages show only access navigation, not authenticated account controls. The source-only deletion-status page is styled consistently but is not enabled on the legacy pilot. Shared navigation and mobile drawer behavior live in the already-allowed `/dashboard.js` asset, so no extra runtime route or framework is required. Only allowlisted, non-sensitive view names enter fragments/history; dates, metric choices, filters, credentials, and JSON pointers remain in memory. Original-field inspection remains click-to-read and bounded to 20 children. Logout/page exit clears displayed evidence and input values, invalidates pending reads, and reloads any restored browser-cache page before reuse.

**App branding:** every account-page template uses first-party copies of the Health.md app artwork for its brand image, 32px PNG favicon, multi-resolution ICO fallback and 180px Apple touch icon. Only `/app-icon.png`, `/favicon.png` and `/favicon.ico` are added to the exact account asset allowlists; they contain no user data and retain the existing no-store, same-origin CSP and MIME protections. The ingest and MCP surfaces do not serve these assets. On the legacy seven-migration pilot, install only the matching three asset-map/GET-allowlist additions in the existing account bundle, verified against its unchanged baseline, instead of installing the newer backend bundle or migrations. Restart only the account listener; preserve writer/ingest/MCP processes, credentials, stored health data, legacy planner assets and the unavailable deletion-receipt route. **Frontend-only rollout compatibility:** the redesigned HTML, `dashboard.js`, and CSS can be installed without upgrading the seven-migration VM backend, changing credentials, or restarting the writer/ingest/MCP services. The browser detects optional session inventory, security history, TAR downloads, supplemental reads, and deletion receipts using fixed same-origin route probes with `credentials: "omit"`; it never reads their response bodies or downloads health data to detect a feature. Only the documented unauthenticated 401 guard enables a feature. A confirmed 404 on the deletion-status route retains the existing password-only pilot deletion request, without inventing a receipt; failed or ambiguous probes hide deletion until retry. Missing inventory retention roles are “Not reported,” never guessed as current or revised. Preserve the live seven-migration planner assets during this rollout rather than installing the newer, backend-dependent provenance panel. Static directory replacement must preserve owner-only permissions, keep a private code-only rollback copy, and verify asset hashes and denial checks afterward; it is not a data backup or a migration authorization.

**Owner-only Explorer (2026-09-28, internal UI/API v1):** `/explore` follows the signed-in overview and applies Shneiderman's overview → filter/zoom → details-on-demand and Tufte-style small multiples. `GET /api/explore/catalog` publishes only the session-bound, non-sensitive reviewed metric IDs/units so the explorer and export library remain usable if a particular chart window cannot be decrypted. `POST /api/explore/chart` accepts 1–31 real calendar days, any distinct subset of the eleven reviewed Apple-v8 daily-summary metrics, and an explicit source/schema filter. A second bounded request may compare another period; the browser aligns by day index and uses a shared labeled Y scale *per metric*, never silently merges different units or dates. Missing, filtered, unsupported and budget-limited days stay distinct from measured zero. Line/bar and zero/data-range axes are presentation choices only. Android v4/v5 and provider values remain inspectable as originals, **not** Apple metric projections. Each request requires the account session, same-origin browser intent, owner-bound SQL, no-store responses and a 48 MiB per-request verified-decryption budget; it never opens MCP to the account origin.

`POST /api/explore/exports` pages 20 owner-bound envelopes (including old revisions and provider-only sidecars) by source, daily schema, declared date-range overlap and current/all pointers. These envelopes contain **no saved profile name or reliable Summary versus Detailed Time-Series discriminator**; filtering by a fabricated app profile is prohibited. An optional archive's presence can be inspected in the original JSON, but `raw_capture_status: not_requested` alone does *not* distinguish Summary from Detailed. `POST /api/explore/node` pages 20 children from an authenticated, hash-verified retained envelope using bounded JSON Pointers, including archived/source/provider fields; long strings are previews, non-integer decimals may be rounded by JSON parsing, and unsafe JavaScript integers are not presented as exact. The existing authenticated `/api/exports/:id/download` remains the exact byte-preserving route to **all original retained fields**. Original fields are only fetched after an explicit click; no third-party assets, client-side persistence, URLs with values, or telemetry. These are internal owner-session APIs, not a version change to mobile exports, the common public health schema, direct protocol, Rust CLI or MCP read scopes. Separately retained supplements are now labeled in original-envelope inventories; original-byte downloads remain unchanged. A future exact app-profile filter requires an explicitly versioned producer field and a migration plan; do not guess profile names from payload shape. No change to saved phone endpoints or tokens.

**Missing-export planning slice (owner session only, not a device handoff):** The overview, Explorer and standalone `/repair` view render one first-party, same-origin `/repair-panel` component: per-day summary and retained-day tables can select an Apple date/metric or whole Apple/Android day, while the library may select a bounded declared range; noncontiguous dates remain editable before preview. This passes only in-memory page events, never health dates or metric choices in URL/navigation state or browser storage. `GET /api/exports` and paged days now include the retained producer `source` so whole-day actions choose the right platform without guessing from a schema version. `/repair` remains a bookmarked fallback. The account session gates both the panel and data APIs. `POST /api/repair/preview` bounds selection to 31 distinct valid logical days no later than UTC tomorrow, one source and explicit detail; it compares owner-bound current pointers, verifies Apple v8 summary projections only for the eleven reviewed metric IDs under a 48 MiB read budget, labels null/unsupported/read-limit/source-conflict separately from a measured zero, and never infers that a phone has data. Android supports **entire days** in this slice, not unreviewed Apple-equivalent metric IDs or Android raw/lossless uploads. `POST /api/repair/drafts` saves only a normalized, 24-hour, **non-launchable** scope under purpose-separated AES-GCM with account + request AAD; it returns success only after exact durable encrypted-row read-back, including after a lost D1 response. `GET /api/repair/drafts` lists at most ten owner-bound active drafts, and idempotent `DELETE /api/repair/drafts/:id` reports success only after exact proof that the scope ciphertext/IV are scrubbed, state is cancelled and no active dispatch remains. Migration `0007_repair_drafts.sql` adds one FK-cascading table and index; writer maintenance deletes expired scopes. All routes remain session-only on the account allowlist, `no-store`, origin-checked for mutations, and denied from public ingestion and MCP. **A supplemental-storage/read substrate is staged behind a server-internal call only; there is no public repair upload route, in-app request review, verified receipt or actionable app link. Separately gated account-only server APIs can queue a 15-minute, review-only draft to an approved device and accept one device claim/resume/decline; they are disabled on live services, and `uploadEnabled` remains false.** Both native entry points reject link variants and display a non-launching notice. `POST /api/repair/supplements` is an owner-session, same-origin, paged and 48 MiB-bounded evidence read; it shows separately verified primary and supplemental values without merging or claiming that a phone was queried. The authenticated export inventories label `supplemental` separately from `current`. Neither this page nor a saved scope changes phone settings, existing daily snapshots or the mobile export contract. See `missing-export-handoff-v1.md` for the remaining safety gates. Before any controlled rollout from the live seven-migration pilot to forward-only migrations `0008`–`0018`, quiesce writer/account/ingest/reader and check database integrity, then restart the writer, check all eighteen migrations and recheck durable upload reservations/orphan scanning, account-key compatibility/rewrapping, deletion-status credentials, ingress, and read-only MCP boundaries. The VM remains in legacy-key mode unless an independently provisioned wrapping-key profile and reader migration are explicitly approved. Do not enable device enrollment, device dispatch or a public supplement upload route. No off-host backup or restore claim is made.
