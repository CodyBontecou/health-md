# Owner-only public account dashboard — deployment contract

`https://healthmd.app/dashboard` is a **temporary redirect** to `https://account.healthmd.app/dashboard`. The static Vercel website must never proxy browser cookies, credentials, exports, or account API requests; its third-party scripts do not run on the isolated account hostname. The same-origin account dashboard has no third-party assets or analytics, uses a strict CSP and a Secure, HttpOnly, SameSite=Strict host-only session cookie. The owner explicitly accepted username/password without MFA for this unbacked single-user pilot; public signup, OAuth, password recovery, and other users are **not** enabled. Do not present this as a general production launch.

**Multi-user source milestone (not live):** the split account Worker now exposes account-owned browser-session inventory/revocation, a 50-entry reviewed security-activity history containing only event types/timestamps, and accepts account deletion only after password reauthentication or an email-link session created within the prior 15 minutes. Disabling the account immediately invalidates session, ingest, and MCP authorization. A durable D1 deletion row is sent to the isolated lifecycle Queue when configured; the scheduled maintenance scan remains a recovery fallback. The consumer removes bounded export and active-intent ciphertext batches before metadata/account completion and never logs identifiers or payloads. Deletion returns one opaque `hmd_del_…` status receipt, stores only its SHA-256 hash, and exposes a no-session status checker that returns only pending/completed until the bounded receipt expiry. The credential stays in memory/manual copy, never a URL or browser storage; an expired credential is cleared without dropping an unfinished deletion job. Event target IDs never leave the server; this history is not an out-of-band security notification. The placeholder Queue, Worker profiles, and production identity mode are not deployed.

The public administration listener runs on loopback **18791**, behind its own nginx loopback proxy **18792**, Tunnel identity, hostname and DNS record. It uses the writer's account database and encrypted-object keys; it is **not** a separately privileged reader like MCP. Its adapter's positive route/method list excludes `POST /api/v1/exports`, signup, raw files, arbitrary paths and MCP. The iPhone writer remains tailnet-only on **18788** and synthetic preview remains upload-disabled on **18787**; do not change the unrelated port 443 route. The MCP reader keeps its distinct read-only OS identity, credentials and public `mcp.healthmd.app` ingress. Reuse neither the MCP Tunnel credential nor its service-account secrets for administration.

The owner may list/download stored exports, page older export and day metadata, export account data as bounded uncompressed TAR pages, view bounded retained-summary charts, manage write-only upload tokens, sign out, request account deletion after password re-entry, and create/revoke per-agent read tokens. Each portability archive contains a manifest plus at most five owner-scoped, hash-verified exact envelopes; it streams after authentication and never stages a plaintext archive in storage. Issuance requires password re-entry and explicit full-export consent for that named agent; new tokens last 1–90 days, are returned only once and cannot be recovered. The reader enforces account scope and revocation at every request. **Existing aggregate-only Muse credentials remain aggregate-only**; no rotation or Grokbot credential is implied. The owner must review the specific provider's retention and handling before copying a credential into its secure store. Do not paste tokens into prompts, URL parameters, chat, logs or tickets. This is still an unbacked pilot: VM/disk/key loss can erase everything permanently. Uploads are limited by quota; unlimited revision retention means time, not space or recoverability.

**Dashboard visualization v1 (owner session only):** `GET /api/dashboard/trends` returns at most 30 calendar days ending on the latest current daily snapshot. It verifies and decrypts only selected current Apple-v8 compatibility envelopes, projects Steps, Total Sleep (seconds to hours), and Resting Heart Rate using the shared metric registry's exact units, and returns null for absent or unverified values; zero is not missing. Android v4/v5, provider data, archive data, prior revisions, absent days, and unsupported units are never silently presented as Apple readings. Unsupported profiles and an exhausted 48 MiB per-request read budget are labeled, not filled in. No new data is stored, no export schema or direct protocol changes, and nothing here queries a live phone or grants a write/read token additional authority. The owner-only response is no-store and uses the existing host-only session. The chart, keyboard-accessible daily table, and responsive light/dark Geist-inspired components are first-party CSS/SVG with no external chart SDK, font, shadcn CDN, or telemetry. `GET /api/exports` additionally returns `storage.dayCount` so the overview counts **all** current snapshots, not only its first 50 paginated rows.

**Owner-only Explorer (2026-09-28, internal UI/API v1):** `/explore` follows the signed-in overview and applies Shneiderman's overview → filter/zoom → details-on-demand and Tufte-style small multiples. `GET /api/explore/catalog` publishes only the session-bound, non-sensitive reviewed metric IDs/units so the explorer and export library remain usable if a particular chart window cannot be decrypted. `POST /api/explore/chart` accepts 1–31 real calendar days, any distinct subset of the eleven reviewed Apple-v8 daily-summary metrics, and an explicit source/schema filter. A second bounded request may compare another period; the browser aligns by day index and uses a shared labeled Y scale *per metric*, never silently merges different units or dates. Missing, filtered, unsupported and budget-limited days stay distinct from measured zero. Line/bar and zero/data-range axes are presentation choices only. Android v4/v5 and provider values remain inspectable as originals, **not** Apple metric projections. Each request requires the account session, same-origin browser intent, owner-bound SQL, no-store responses and a 48 MiB per-request verified-decryption budget; it never opens MCP to the account origin.

`POST /api/explore/exports` pages 20 owner-bound envelopes (including old revisions and provider-only sidecars) by source, daily schema, declared date-range overlap and current/all pointers. These envelopes contain **no saved profile name or reliable Summary versus Detailed Time-Series discriminator**; filtering by a fabricated app profile is prohibited. An optional archive's presence can be inspected in the original JSON, but `raw_capture_status: not_requested` alone does *not* distinguish Summary from Detailed. `POST /api/explore/node` pages 20 children from an authenticated, hash-verified retained envelope using bounded JSON Pointers, including archived/source/provider fields; long strings are previews, non-integer decimals may be rounded by JSON parsing, and unsafe JavaScript integers are not presented as exact. The existing authenticated `/api/exports/:id/download` remains the exact byte-preserving route to **all original retained fields**. Original fields are only fetched after an explicit click; no third-party assets, client-side persistence, URLs with values, or telemetry. These are internal owner-session APIs, not a version change to mobile exports, the common public health schema, direct protocol, Rust CLI or MCP read scopes. Separately retained supplements are now labeled in original-envelope inventories; original-byte downloads remain unchanged. A future exact app-profile filter requires an explicitly versioned producer field and a migration plan; do not guess profile names from payload shape. No change to saved phone endpoints or tokens.

**Missing-export planning slice (owner session only, not a device handoff):** The overview, Explorer and standalone `/repair` view render one first-party, same-origin `/repair-panel` component: per-day summary and retained-day tables can select an Apple date/metric or whole Apple/Android day, while the library may select a bounded declared range; noncontiguous dates remain editable before preview. This passes only in-memory page events, never health dates or metric choices in URL/navigation state or browser storage. `GET /api/exports` and paged days now include the retained producer `source` so whole-day actions choose the right platform without guessing from a schema version. `/repair` remains a bookmarked fallback. The account session gates both the panel and data APIs. `POST /api/repair/preview` bounds selection to 31 distinct valid logical days no later than UTC tomorrow, one source and explicit detail; it compares owner-bound current pointers, verifies Apple v8 summary projections only for the eleven reviewed metric IDs under a 48 MiB read budget, labels null/unsupported/read-limit/source-conflict separately from a measured zero, and never infers that a phone has data. Android supports **entire days** in this slice, not unreviewed Apple-equivalent metric IDs or Android raw/lossless uploads. `POST /api/repair/drafts` saves only a normalized, 24-hour, **non-launchable** scope under purpose-separated AES-GCM with account + request AAD; `GET /api/repair/drafts` lists at most ten owner-bound active drafts, and `DELETE /api/repair/drafts/:id` erases a cancelled draft's ciphertext. Migration `0007_repair_drafts.sql` adds one FK-cascading table and index; writer maintenance deletes expired scopes. All routes remain session-only on the account allowlist, `no-store`, origin-checked for mutations, and denied from public ingestion and MCP. **A supplemental-storage/read substrate is staged behind a server-internal call only; there is no public repair upload route, in-app request review, verified receipt or actionable app link. Separately gated account-only server APIs can queue a 15-minute, review-only draft to an approved device and accept one device claim/resume/decline; they are disabled on live services, and `uploadEnabled` remains false.** Both native entry points reject link variants and display a non-launching notice. `POST /api/repair/supplements` is an owner-session, same-origin, paged and 48 MiB-bounded evidence read; it shows separately verified primary and supplemental values without merging or claiming that a phone was queried. The authenticated export inventories label `supplemental` separately from `current`. Neither this page nor a saved scope changes phone settings, existing daily snapshots or the mobile export contract. See `missing-export-handoff-v1.md` for the remaining safety gates. Before any controlled rollout from the live seven-migration pilot to forward-only migrations `0008`–`0014`, quiesce writer/account/ingest/reader and check database integrity, then restart the writer, check all fourteen migrations and recheck durable upload reservations/orphan scanning, account-key compatibility/rewrapping, deletion-status credentials, ingress, and read-only MCP boundaries. The VM remains in legacy-key mode unless an independently provisioned wrapping-key profile and reader migration are explicitly approved. Do not enable device enrollment, device dispatch or a public supplement upload route. No off-host backup or restore claim is made.

**Source-only examples:** `healthmd-account-dashboard.service.example`, `healthmd-account-proxy.conf.example`, `healthmd-account-proxy.service.example`, `healthmd-account-tunnel.service.example`. The account server fails startup unless its separate origin is exactly `https://account.healthmd.app`, the private writer origin is the existing `*.ts.net:18788` HTTPS endpoint, the explicit loss acknowledgement is present and port 18791 is configured. The account proxy must suppress request/error logs and disable disk buffering; Tunnel ingress must match only the account hostname and otherwise return 404. The public domain should serve no account page or API before origin and endpoint tests pass. Use a dedicated Tunnel and proxied DNS record, never the Vercel origin or public writer route. Cloudflare terminates TLS and may process authorized requests.

**Live pilot status (2026-09-28):** The owner authorized Cloudflare in a private headless flow. A distinct account Tunnel and explicit DNS route now serve `https://account.healthmd.app/login` through a separate loopback proxy and writer-authority account process. These three units are enabled for reboot; the MCP Tunnel/reader identity, tailnet-only upload writer and unrelated website route remain separate. The Tunnel-only credential is root-owned and readable only by its dedicated service group. The broad origin certificate and one-time login/provisioning logs were removed after the Tunnel started successfully from its per-Tunnel credential. Public unauthenticated account/export/token APIs returned 401, `POST /api/v1/exports` returned 404, and static login returned 200 with `no-store`, strict CSP and no third-party scripts; the prior aggregate Muse token still lists six tools and the separately authorized full-export token lists eleven. Password-authenticated browser interaction has not yet been exercised with the owner's real credentials. The account runtime now advertises the separately verified `https://api.healthmd.app/api/v1/exports` write-only endpoint; the original tailnet writer remains available for saved targets. The website's `/dashboard` redirect is committed but not yet on Vercel production. Any future Cloudflare provisioning requires new private owner authorization rather than reuse of the MCP credential.

Before activating: review current live source/migration hashes and DB integrity with writer and MCP temporarily paused if any migration is needed; install bundles with owner-only permissions and no secrets in source; test the account listener and proxy locally with synthetic requests, including denied public ingest and wrong-host/Origin attempts; confirm public account unauthenticated `/api/agent-tokens` and `/api/exports` return 401, public `POST /api/v1/exports` returns 404, authenticated responses have `no-store`, and old aggregate credentials still list exactly six MCP tools. Validate a disposable full-export credential on public MCP, revoke it and confirm 401 without printing health data. Confirm writer, reader, proxy, Tunnel and unrelated website still work. Route the Vercel `/dashboard` redirect **only after** the dedicated dashboard is live; update public privacy/terms and translations to acknowledge opt-in retained exports before public release.

CLI parity is staged. The CLI and its portable MCP query the foreground iPhone for typed responses and can capture a broader raw corpus. This cloud endpoint only queries **retained API-export JSON**; it cannot query the phone, synthesize missing records, or ingest Android Raw API Snapshot artifacts. Preserve distinct truthful profiles and versioned public contracts before adding shared query names or claiming equivalent coverage. No new mobile sync or expanded data collection is authorized by this dashboard deployment.
