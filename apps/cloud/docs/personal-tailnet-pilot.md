# Personal Tailnet pilot — readiness plan

## Current state (not production)

`https://<your-vm>.<your-tailnet>.ts.net:18787/` is the **synthetic, tailnet-only** dashboard preview. It is forwarded by a separate Tailscale Serve HTTPS listener to a loopback Wrangler development server. The existing port-443 Tailscale route to another service is untouched. The preview uses a reserved synthetic email, a development sign-in link, local emulated D1/R2 storage, and `SYNTHETIC_PREVIEW_ONLY=1`. `POST /api/v1/exports` and `POST /api/ingest-tokens` both return HTTP 403 before touching health data. It is not an endpoint for Health.md's iOS API Export target.

A **separate** personal-MVP Node service runs under a dedicated system user on loopback port 18788 and has its own tailnet-only HTTPS route. It has private SQLite/ciphertext storage and independently generated keys. A single `owner` account was bootstrapped with a generated password delivered through a root-only file as documented in the README. The owner has used a write-only export token to send real HealthKit records. Personal use of real HealthKit records is still health-data processing. A private tailnet and local disk do not provide off-host durability or incident recovery; the owner accepted possible permanent loss for this experiment. Never remove the synthetic guard to make the emulated Worker look production-ready.

## Owner decisions and outstanding choices

1. **Hosting boundary selected:** isolated Node 24 VM service with SQLite metadata and application-encrypted private filesystem objects, behind a separate Tailscale HTTPS port 18788. Its adapter has synthetic integration tests and is installed as an **unbacked personal MVP, not a production service**. Wrangler's local D1/R2 emulator remains preview-only; do not share the existing Postgres or another app's state.
2. **Retention selected:** `REVISION_RETENTION_DAYS=unlimited` keeps current snapshots and every accepted older revision until an explicit account-deletion request; no age-based purge runs. This is **unlimited time, not unlimited storage**: the existing 1 GiB best-effort account quota and 25 MiB per-export limit still apply. Account-deletion completion/progress, orphan reconciliation, and an erasure SLA still need qualification.
3. **Unbacked disposable pilot selected:** the owner explicitly accepted permanent-loss risk and chose not to add an off-host backup or restore/key-recovery gate for this single-user experiment, including a separately authenticated public read-only MCP connector. Any provider snapshots are unverified. Loss of this VM, SQLite state, keys or disk can permanently destroy retained exports; unlimited retention does not imply recoverability. Keep the warning visible and pass private-storage, authentication, least-privilege reader, ingress, erasure/reconciliation and security tests; do not describe the pilot as durable or production-certified.
4. **Identity selected:** offline-created single-user username/password; no HTTP signup or password reset. Losing the password or encryption keys can permanently destroy access. Tailnet membership is an additional boundary for the writer, not a substitute for the app's write-only per-device token; any public reader must use a separate read credential.
5. **Legal/privacy:** truthfully disclose the unbacked health-data pilot and review any public privacy statements before wider availability. Independently commissioned security/privacy sign-off is not required for this owner-operated pilot. Obtain explicit owner consent and review provider retention before issuing a read credential to a third-party agent.

## Implementation and qualification gates

- **Storage:** independent persistent VM service (or production Cloudflare bindings), non-root systemd service, least-privilege file permissions, private encrypted objects, atomic per-account quota reservation, failed-write/orphan recovery, idempotent receipt semantics, and bounded large-record handling.
- **Security:** proper HTTPS origin and Secure `__Host-` cookie, reverse-proxy trust restricted to the local Tailscale ingress, no development magic-link URLs, per-account auth and write-only token revocation, production request/error logging review, patch/update and abuse limits, negative cross-tenant and CSRF tests.
- **Lifecycle:** self-service export and account deletion with durable progress, revision retention, object/metadata reconciliation, key IDs and loss warnings. No 2xx until the encrypted object and metadata commit to this VM; no off-host durability or recovery is promised.
- **Compatibility:** synthetic Apple API v1/v2 and Android v4 tests, physical iPhone API Endpoint test on the tailnet with a *separate explicitly authorized test HealthKit dataset*, batch/oversize/partial/retry QA, and no raw Android snapshot or cloud MCP claim.
- **Pilot release:** verify account-bound auth, dedicated reader identity, no write/data-leak path, bounded queries, HTTPS ingress and explicit owner consent per external agent. The pilot is deliberately unbacked and carries no independent-audit or recovery claim. Never change the synthetic preview's `SYNTHETIC_PREVIEW_ONLY=1` guard.

The VM writer remains a tailnet-only service; the separately authenticated public read-only MCP pilot is documented in [`mcp-public-readiness.md`](mcp-public-readiness.md). Neither pilot is a general production cloud release.
