# Core, contracts and CLI/MCP tasks

Read this branch for portable core, protocol, operation, CLI/MCP or registry work. The [design reference](../../architecture/javascript-unified-layer-design-reference.md#core-and-protocol-implementation-work-packages) remains the acceptance authority. Use `manage.py reference ID` for the exact C/K/O/F/V obligation. Claim one behavior/contract/profile boundary at a time.

## First slice

`BASE-CORE`, `BASE-CLI` and `BASE-HOST` pin actual source, contracts, fixtures, state and consumers. `LOCAL-DECISION` reconciles the selected local architecture and `TOOLCHAIN-PINS` records reproducible portable tool versions. Those results enable `TS-FOUNDATION`, exact value codecs, a registry reader, catalog normalization and a bounded fake-source query. Separate thin CLI and MCP candidate adapters call that same function; `SLICE-PARITY` compares their canonical requests, source calls, receipts and interruption. Production launchers/source evaluation stay on their current authority.

The first slice does not implement the whole evaluator, ship a Node replacement, relocate the registry or install React. Its CLI/MCP candidate entrypoints remain explicit development paths until separate distribution/admission tasks pass. Missing cloud decisions do not block it. Required new scripts become executable and documented in the task that creates them.

## Integration and completion

Package manifests/locks, public interfaces, contract revisions and generators have one writer. Implementations can run in parallel only after an accepted interface and disjoint module/test claims. Shared-core changes retain all affected consumer gates during coexistence. New canonical expectations come from independently reviewed source/contracts, never solely from the candidate implementation.

A task's portable result records exact contract/profile/fixture/runtime fingerprints. Native and signed distribution tasks admit that result separately. Keep Rust comparators/reference source until independent fixtures, retained-state recovery, promotion and the rollback window permit their specific retirement. Whole K02/K03/K05/O02 or M03/M04 assignments must be decomposed before coding.
