The coordinator recommends **USD 500/month planning allowance**, with **USD 200–300/month for a controlled beta**; neither figure is an owner-accepted spending ceiling or product pricing decision.

Recommend **Node 24 / Effect 4 common operations in an ECS Fargate image, RDS PostgreSQL, private S3 and a single-region customer-managed KMS key in `us-east-1`**. ## Architecture and authority boundaries

The fixed requirements come from [the cloud design](../../../architecture/javascript-unified-layer-design-reference.md#optional-hosted-exports-and-remote-mcp), [cloud work packages](../cloud-release.md) and the accepted [43 cloud fault expectations](cloud-fault-cases.json), not from the historical pilot's defaults. Optional server-readable consent, local account-free operation, independent writer/owner/agent authority, source/purpose/recipient/detail/range grants and complete historical originals remain mandatory. Sign-in, purchase, SDK permission and enrollment identifiers grant no new data authority. Practice, Wake, website and pricing telemetry remain outside this hosted data boundary.

| Boundary | Recommended candidate design | Proof still required |
| --- | --- | --- |
| Runtime | One locked Node/Effect image and common programs with explicit host Layers; bounded stream/chunk, SQL, objects, crypto and queue ports | Exact Linux/image/native dependencies, Effect identity, source-license/SBOM and bounded host graph; no Node-host Layer assumed Worker-compatible |
| SQL | Private RDS, separate migration owner; runtime roles non-owner, non-superuser, no `BYPASSRLS`; tenant predicates plus enabled/forced RLS where applicable, parameterized SQL and transaction-local context | Wrong-tenant adversarial tests, pool reset/reuse, security-definer/constraint/error leakage, every table/policy and source/destination grant path |
| Objects | Private S3, opaque tenant/source/artifact identities, staging namespace and verified sealed objects; no public URL as authorization | IAM/bucket/public-access/version policies, complete authentication units, bounded spool, listing/cursor/object-key isolation and provider fault behavior |
| Keys | Single-region KMS customer-managed symmetric root; envelope data keys with opaque context, narrowly separated wrap/unwrap/lifecycle IAM | Regional custody and audit inventory, exact frame/KDF/authentication design, active-grant checks before unwrap, plaintext-key lifetime/cache eviction, key version and erasure/restore behavior |
| Authority | Primary-current source/purpose/recipient/job and latest independent suppression frontier before every page, raw materialization, commit and delivery | No stale replica or old snapshot authorization; bounded current-check/publication seam, reentry/cancel/revoke races, recipient copy limits |
| Operations | Content-free logs, explicit region/copy inventories and quarantine restore; no blanket “US-only” claim | All stores, logs, backups, auth/support/subprocessors, code/keys/caches/retries and actual failover/recovery evidence |

PostgreSQL owners normally bypass RLS; superusers and `BYPASSRLS` always bypass it. RLS is therefore defense in depth rather than a substitute for scoped runtime roles and current application grants. [PostgreSQL row security](https://www.postgresql.org/docs/current/ddl-rowsecurity.html). ECS task roles provide task-scoped AWS credentials; keep execution/image-pull and application roles distinct. Provider IAM does not establish application tenant authority. [ECS task IAM roles](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/task-iam-roles.html).

Objects and SQL are separate transactions. Reserve quota/idempotency durably; receive invisible staging; verify a complete authenticated unit/ordered manifest; seal the exact object; then commit original ledger identity, once-only accounting and projection outbox in one SQL transaction. Outbox delivery is retryable and idempotent. Cancellation owns only its allocations and waits cleanup ACK. A lost SQL response is **ambiguous** until exact durable postconditions reconcile it; do not fabricate rollback, release unknown reservations or delete a possibly committed winner. A confirmed commit requires separately authorized erasure. Stored receipts identify original commitment; ready receipts identify projection version/frontier/coverage. See the independent [fault model](cloud-fault-model.md).

Restore starts quarantined and consults a complete authenticated latest deletion/revocation journal whose freshness authority is outside the restored backup lineage. Replaying an old outbox, key or snapshot cannot restore access. This requires a separately durable suppression authority/copy, not merely another table restored from the same snapshot. Inventory immutable containing originals, object versions, SQL projections/indexes, caches, replicas, temporary copies, logs and backups. S3 delete markers do not purge noncurrent versions; retained RDS manual snapshots require lifecycle handling; KMS deletion has a 7–30-day waiting period. Neither a regional key nor its scheduled deletion proves tenant crypto-erasure or recovery safety. [S3 versions](https://docs.aws.amazon.com/AmazonS3/latest/userguide/DeletingObjectVersions.html), [RDS deletion/snapshot lifecycle](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/USER_DeleteInstance.html), [KMS deletion](https://docs.aws.amazon.com/kms/latest/developerguide/deleting-keys.html). Use a single-region key rather than opting into replicable Multi-Region keys; actual custody/copy inventory remains unqualified. [KMS key concepts](https://docs.aws.amazon.com/kms/latest/developerguide/concepts.html), [Multi-Region keys](https://docs.aws.amazon.com/kms/latest/developerguide/multi-region-keys-overview.html).

## Cloudflare alternative: viable, with unresolved regional/key/SQL costs

Current **D1 and R2 both support `us` jurisdictions**. D1 restricts database execution/storage (including jurisdiction-limited replicas); R2 supports US object placement. Configure jurisdiction at creation; location hints are not equivalent guarantees. The earlier assumption that US object/database jurisdiction was unavailable is obsolete. [D1 data location](https://developers.cloudflare.com/d1/configuration/data-location/), [R2 data location](https://developers.cloudflare.com/r2/reference/data-location/).

Regional Services limits custom-domain TLS termination and Worker execution. Worker **code and secrets still deploy globally**; outgoing subrequests, Queue and Cron triggers are excluded from that regionalization. Data Localization Suite is an **Enterprise-only paid add-on**, so the metered estimate below is not an all-in regional topology quote. Obtain actual entitlement, pricing and all trigger/subprocessor controls before recommending deployment. [Workers regional caveats](https://developers.cloudflare.com/data-localization/how-to/workers/), [Data Localization Suite](https://developers.cloudflare.com/data-localization/).

Workers supports streaming and many Node APIs, but its Node compatibility includes partial implementations and nonfunctional stubs. A portable Effect program can share semantics; a Node host adapter and its exact graph need separate Worker qualification. [Worker streams](https://developers.cloudflare.com/workers/runtime-apis/streams/), [Node compatibility](https://developers.cloudflare.com/workers/runtime-apis/nodejs/).

D1 is a SQLite service, so the PostgreSQL RLS design cannot simply be copied. Its maximum paid database is **10 GB**, with **2 MB row/string/BLOB** and 30-second SQL-query limits. A 100-GB projection model needs sharding: illustrative 20 shards averaging 5 GB, or per-tenant databases, with explicit tenant placement, hot-tenant skew, rebalancing and cross-shard transaction/authority limits. This is not measured capacity. [D1 limits](https://developers.cloudflare.com/d1/platform/limits/). D1 `batch` is transactional within its database; it does not commit R2. `first-primary` makes only the first Session query primary; subsequent queries may use replicas. Keep a separately current primary grant/frontier path for **every** page, not a session bookmark treated as fresh consent. [D1 database API](https://developers.cloudflare.com/d1/worker-api/d1-database/).

D1/R2 at-rest encryption is provider-managed. R2 SSE-C permits customer-supplied keys, while its S3 compatibility lacks SSE-KMS key/context headers; neither provides the proposed nonexportable regional application KMS custody by itself. A concrete envelope-key service design and its price/residency are unresolved. [D1 security](https://developers.cloudflare.com/d1/reference/data-security/), [R2 security](https://developers.cloudflare.com/r2/reference/data-security/), [R2 S3 compatibility](https://developers.cloudflare.com/r2/api/s3/api/). D1 Time Travel is always enabled, with paid 30-day/free 7-day history; restore does not remove older bookmarks. Its convenience does not qualify no-backup or immediate-erasure promises. [Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/), [plan limits](https://developers.cloudflare.com/d1/platform/limits/).

Cloudflare remains a reasonable low-idle-cost alternative if H01 proves an exact Worker host, tenant isolation/shard design, current-authority path, regional trigger inventory and key custody, and an Enterprise quote is acceptable. The present evidence supports choosing AWS as the simpler fit for this particular authority/recovery design; it does not prove AWS cheaper or Cloudflare incapable.

## Explicit hypothetical workload

**1,000 cloud-active users are an assumption, not a consequence of 1,000 app DAU.** Let cloud participation be `f`; the modeled cohort is `1000 × f`, while historical data from inactive users may still cost money. Below `f=1`, 730 hours/month (30.4167 days), 30 API/agent queries per user/day gives **912,500 queries/month**, about 0.347 average queries/second. Peaks, concurrency, historical scans, ingest and reindexing dominate sizing; this average is no capacity benchmark.

Use **decimal GB = 10^9 bytes** for common original-data quantities: 1,000 GB starting retained compressed originals, 150 GB new originals arriving evenly, 1,150 GB month-end and 1,075 GB average. This explicitly normalizes the scratch AWS model's 1,024-GiB start versus the Cloudflare model's 1,000-GB start. AWS storage below converts this to 1,001.17 GiB average. Provision RDS with 100 GiB; the Cloudflare comparison assumes 100 GB of projections/indexes/ledger, not a guaranteed identical capacity or a forever-fixed SQL footprint. No retention/deletion policy is selected.

Assume 300,000 object writes/list/seal/multipart operations, 2,000,000 object reads, two KMS requests per query plus 300,000 ingest requests, 100 GB client internet egress, 100 GB routed outbound NAT traffic **only where explicitly priced**, 5 GiB content-free log ingestion, and an additional 100 GiB of charged RDS backup beyond any included allowance. At 1-MiB authenticated chunks, 150 decimal GB already implies roughly 143,000 data chunks; headers/manifests/retries add calls. Actual paging/grant checks/outbox/auth/job traffic, indexes, replay and reprocessing must be measured; object bytes do not determine row counts or key-call fanout.

### Growth and high-cost sensitivities

With no deletion, every additional 150 decimal GB retained adds approximately **$3.21/month S3** or **$2.25/month R2** to the next run-rate; after six months, originals alone reach 1,900 GB. Extra versions/backup copies add again. SQL at +10 GB/month adds $7.50/month D1 storage and shard/headroom pressure; RDS must increase provisioned capacity rather than pretending 100 GiB is permanent. An extra task costs about $36.04/month; t4g→m7g Multi-AZ adds $151.84 in this table. Another 1,000 GB billable internet egress is roughly $90 at the initial AWS tier before tiering/allowances; R2 internet egress is free under its documented service pricing, while other paths/providers may charge. Per-record KMS fanout is dangerous: 912,500×1,000 requests gives approximately **$2,737.44/month plus the $1 key**, versus the bounded envelope model. Cache savings must never bypass current grants or broaden plaintext-key lifetime. [KMS pricing](https://aws.amazon.com/kms/pricing/), [data-key caching constraints](https://docs.aws.amazon.com/encryption-sdk/latest/developer-guide/data-key-caching.html).

Budget ranges exclude external model tokens, staff/on-call/security review, legal/compliance, paid support/WAF, authentication-plan fees, tax, multi-region recovery, independent suppression-journal infrastructure beyond the small allowances, unexpectedly large history and incident/reindex campaigns. They include no SLA, retention promise, deletion deadline or purchased commitment.

## Identity and key-count sensitivity remain separate

Application DAU, cloud-active DAU and authentication MAU are different quantities. A hypothetical 1,000 cloud users each day could represent the same 1,000 monthly users or up to roughly 30,000 distinct monthly users. Q-CLOUD-IDENTITY remains unselected: the infrastructure table selects neither Cognito nor self-hosted authentication. Managed identity, transactional email, SMS, federation and OAuth machine-to-machine token costs require a separate forecast. As one current example, Cognito Lite/Essentials direct/social sign-in has 10,000 free MAU per account/organization; SAML/OIDC federation has 50, Plus has no free MAU, and machine-to-machine token requests have no free allowance. Essentials direct/social MAU above its allowance costs $0.015 each: hypothetical 30,000 MAU adds $300/month before messaging and other charges. The allowance may already be consumed elsewhere in the account. These facts do not select a provider or authentication policy. [Current Cognito pricing](https://aws.amazon.com/cognito/pricing/).

The KMS table assumes one unrotated customer-managed key. The first two automatic/on-demand rotations each add $1/month; more tenant/environment keys multiply storage and rotation charges. A shared customer-managed key is not a customer-specific erasure mechanism. Envelope-key lifecycle, independently current suppression/revocation authority and erasure of every retained copy still require reviewed implementation and recovery proof. [Current KMS pricing](https://aws.amazon.com/kms/pricing/). The $500 planning recommendation is therefore a core-infrastructure allowance with headroom, not an all-in guarantee when identity or other excluded services are chosen.
