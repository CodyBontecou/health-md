# Personal data candidate contract

This is a bounded planning draft for one logical health, location and device-usage dataset. It defines a typed record/selection/coverage boundary for later common Effect operations; no codec, repository, native source, export profile or public operation is implemented or admitted. Private `candidate.*` names, revision 1 and synthetic identifiers are fixture labels pending PERSONAL-CONTRACT-REVIEW. Public profile/version/product identity decisions remain unselected.

The companion [literal cases](personal-contract-cases.json) is the independently authored expectation authority for this draft. It contains one health fact, one location point and one usage aggregate in one selected combined manifest, plus a short observed foreground session and rejection/authority examples. Values and identities are synthetic. Source pins and RFC6901 semantic evidence are recorded there; selected-value SHA uses canonical UTF-8 JSON with sorted keys, compact separators and unescaped Unicode. The accepted BASE-DOMAINS ledger retains 281 routes, 1141 semantic leaves and 308 source pins; this task reviews scoped evidence, not the whole donor catalog again.

## Envelope and lineage

A record has `domain` (`health`, `location`, `device_usage`), a domain-specific `payload_kind`, independently versioned payload, stable `record_id`, immutable `lineage`, source-native time and typed payload. A record reference binds dataset identity/revision, source identity/revision, device plus installation scope, source purpose, original record identity and record revision. Device, installation, original record identity, observed/captured/imported/uploaded times and source provenance use explicit known/unknown/absent states. A descriptive device name/model, Family Controls token, app label, hash or mutable app preference is not durable device/install identity or authenticated source authority.

Preserve original native UUIDs/ordinals/source IDs where present. Missing lineage remains unknown. An import may add a stable artifact/partition/ordinal identity and immutable import provenance; it must not claim that this is the missing original UUID, device or session relationship. Rechunking, retry, paging and device display-name changes never mint a different original identity. Same lineage key and same original bytes is an idempotent replay; different bytes under that key conflict unless a reviewed explicit source revision/correction policy applies. Distinct sources/installations are retained separately, with source overlap explicit rather than guessed deduplication.

Original observations remain immutable. Corrections, tombstones and derivations append independently identified lineage links to original records, with original/corrected values, algorithm/revision/selection inputs, reason and available source timestamps. Missing correction times stay unknown. Undo appends reversal rather than rewriting original capture. Visit boundary defaults or Core Location distantPast/distantFuture sentinels do not become observed instants; inferred outings remain distinct from explicit recording sessions. Full visit/place/photo/correction/queue/archive grammars are later scoped tasks, not hidden in this slice.

## Exact values, time and civil scope

Numbers retain tagged finite IEEE-754 binary64 lowercase 16-hex bits including negative zero, canonical signed i128 or unsigned u128 decimal strings, and explicit canonical units/statistics. Source integer counters/ordinals retain u64 strings. Health native semantic IDs/statistics/profile identity and original exact values are retained; a fixture `synthetic.health.*` ID is not a registry mapping proposal. Location coordinates, accuracy, altitude and speed retain native Double bits with degree/meter/meter-per-second units. Absent speed/altitude is absent, not zero. Accuracy and source quality are independent from timestamp storage precision.

Time is a tagged union: canonical i64 Unix seconds plus 0..999999999 nanos when supplied at that representation, or original binary64 epoch seconds with an explicit epoch reference (Unix or Apple reference 2001) when source storage is floating point. Duration retains source representation and basis. Do not manufacture source nanosecond accuracy by converting a Double or round through ISO text, JavaScript Number/Date, milliseconds or whole-second legacy strings. An original text timestamp may be retained as source evidence, but missing offset/reference or ambiguity prevents treating it as an exact instant. Cross-representation comparisons require separately reviewed lossless conversion; keep source representation when conversion is lossy.

Source offset, native calendar timezone, civil owner date and owner-rule revision are distinct explicit fields, each potentially unknown. Current host timezone never supplies missing historical timezone or reassigns native owner dates. Bucket/query intervals are explicitly half-open; civil scopes separately state inclusive date bounds and native calendar evidence. Observed, captured, imported and uploaded instants stay independent. Current freshness does not imply historical coverage. Epoch precision, acquisition resolution and uncertainty have separate labels.

## Domain meaning and overlap

`health_fact` preserves source observation/SDK aggregate/statistic, native semantic identity and units; GPS path distance does not alias HealthKit/Health Connect walking/running distance. Existing Apple health v8 and Android frozen v4/analytical v5 grammar, bytes and all consumer fixtures remain immutable.

`location_point` is an original location observation with available accuracy/quality. Outliers may be marked, but filtering/route snapping/inference cannot overwrite raw facts. A derived visit/outing is separately identified with source certainty and algorithm inputs. Original missing watch device/session linkage is not reconstructed from timestamps alone.

`usage_aggregate` contains source total duration over a bucket, its source device scope/statistic/precision and available app identity. Bucket boundaries do not describe launch/close events. A ten-minute source total in a one-hour bucket stays ten minutes; interpolation across the entire bucket is a new derivation, not a raw observation. Daily/hourly replacement requires explicit reviewed overlap-group/source/device/statistic/revision precedence; retain originals and never add overlapping projections. Unknown cross-device overlap prevents an invented person-total.

`foreground_app_session` contains observed or explicitly uncertain start/end boundaries, app identity, duration basis and optional independently granted details. Future macOS capture must retain every observed short session. Existing discarded sub-two-second, pre-collector, deleted, negative-clock and unflushed crash-tail history is not reconstructable. Full available native donor history must be retained beyond the 365-day mirror or 370-key mobile view. iOS historical usage is honestly aggregate/bucket data; exact session feasibility remains required S06. Android donor UsageEvents reconstruction is deferred prototype evidence with lookback/open-tail/locked/null/checkpoint gaps; Health.md usage remains planned pending S01 proof, not shared production support.

## Coverage and capabilities

Coverage is scoped to source/device/install/payload kind/detail/time interval and snapshot, with `complete`, `partial`, `unavailable` or `unknown`, reasons, known intervals, gaps, source update time and evidence reference. Complete requires explicit qualified source evidence for that exact scope and detail; no record count, successful empty response, SDK observation flag, imported mirror or synthetic receipt proves broader completeness. Unavailable is a source/policy capability outcome; unknown means not established. Denied, locked, excluded, not-observed, expired and retention loss remain reason codes. Known zero requires an actual value or source completeness evidence that establishes zero; unknown/unavailable never becomes zero.

Capability classifications retain `shared`, `apple_only`, `android_only`, `unavailable`, `planned` with source-backed reasons/targets. Capture permission, source-purpose admission, display, local query, export eligibility and individual destination/agent sharing grants are independent, including title, exact location and other detail scopes. Standard iOS report sandbox display is not data-export authority. iOS data access needs separate production OS/entitlement/region/account/device/one-app/purpose/per-destination proof. Snapshot IDs/sidecars/source strings are bindings, not authentication. No CLI flag or donor source adoption grants OS permission or source/export entitlement.

## Selection, grants and exclusion

A request freezes logical dataset/revision, domains, source IDs/revisions, device/install pairs, payload kinds/statistics, exact time/civil bounds, detail projection, destination and strict/allow-partial policy. Narrower scoped export and combined export query the same logical dataset and source coverage. One physical store is not required. One common operation applies current caller/source-purpose/detail/time/destination grants before materialization and again for each page/commit; cursor binding includes caller, dataset/revision, source, purpose, selection, snapshot, grant revision and expiry. No automatic scope union or cross-domain association is inferred.

Strict denied/unsupported requested scope emits no partial deliverable. Explicit allow-partial reports omitted scope/status without payload or unauthorized source/detail identity leakage; manifest cannot become complete. Safe errors contain only fixed codes/authorized counts/revisions/hash references, never values, coordinates, dates, original record IDs, retention tokens, window titles or raw parser/provider/Effect errors. A later concrete codec must independently prove unknown-field, Unicode, exact-number, array/order/bounds and immutable ownership policy; this document alone is not that proof.

Browser application duration is allowed as app usage under its own grants; missing human display label does not remove an otherwise identified app. Browser URLs/domains/page/window/tab titles/history, extension events, keyboard/input/mouse content and related stores remain excluded. Classify browser applications before calling a title API. Unknown app classification fails closed for title acquisition. A title grant cannot override browser exclusion. Ordinary nonbrowser desktop window-title observations require their own supported API/signed channel/capture/detail grants; missing, empty, withheld, excluded and not-observed titles remain distinct. Incoming donor material must be eligibility-validated before observation/copy/staging/queue/persistence/egress; never create a payload quarantine copy for excluded fields. An inert field-presence/code report may identify excluded classes. Donor originals and readers remain unchanged for rollback.

## Manifest, bounds and later authority

The draft combined manifest carries selected record partition references, source snapshot IDs, exact selection, coverage, available source identity and projection-policy revision. It contains all three selected domains without implicit cross-domain correlation. A summary is a derived projection; a selected-record manifest is not a complete native archive. Bounded pages/partitions allow all available authorized retained history without a dashboard-age cap. Proposed guards are 64 KiB raw UTF-8 per candidate record, 1 MiB per page, 4096 records/page, 512 selectors/request and one queued page. These unmeasured candidate limits are not production memory, latency, storage or retention budgets; large source structures require separately reviewed bounded partition/reference representation, never silent truncation. No whole-lifetime in-memory document is implied.

CLOUD-FAULT-MODEL retains complete-stream authentication/invisible staging/current grants/SQL-object split ledger, outbox, idempotency, quota, cancellation, restore-after-delete suppression and recipient-copy limits. This candidate does not choose cloud provider, region, keys, retention, identity/billing or endpoint policy. Upload enrollment and external-agent access are separate authorizations.

A complete donor transfer additionally needs all permitted original native facts, identifiers, corrections/annotations/categories, historical snapshots and source policy, settings, pending/ack queues and retry state, conflict/Undo/replay/crash/rollback manifests. Credentials, purchases/trials, endpoint configuration, armed schedules, CloudKit/Worker services, analytics and donor licenses/source admission are separate decisions and qualifications. No donor import, live store/collector, account, key, destination, service or permission is touched here.

PERSONAL-CONTRACT-REVIEW must resolve the bounded draft before independently reviewed codecs/repository/combined synthetic slice. Full source catalog/protected storage/replay/correction/retention, native/physical capture and source eligibility, serializers/profile/public names, exact consumers and migration/rollout/retirement remain separate tasks. Q-DONOR-SOURCE/Q-DONOR-SUPPORT and purpose/channel/public identity choices remain open; initial labeled iOS aggregates do not close S06. All current native/Rust health authority, donor readers/data, namespaces and frozen profiles remain the rollback route.
