## Concrete dependency and authority boundaries

The portable candidate package has contracts/exact codecs, pure core/domain/protocol, dataset/source/destination interfaces, complete Effect programs and React-free feature models. Presentation is separately built `packages/healthmd-ui`. Host Layers supply bounded owned SDK capture facts, crypto/randomness/credentials/transport, transactional repositories/inbox checkpoints, durable journal/stream and safe destination primitives. Immutable settings/batches/results, explicit cancellation/checkpoints and implementation-neutral `EngineBuildInfo` cross coarse seams. UI cannot reach past operations into capture/secrets/journals. Each VM has one Effect/contract module instance; React/Node/native/DOM/env dependencies stay outside portable entrypoints.

`TOOLCHAIN-PINS` verifies exact Node/npm/Effect/TypeScript/test/bundle pins before `TS-FOUNDATION` creates an independently locked executable portable package. Portable CI/import checks establish dependency identity and a clean fake-capability boundary. `CODEC-VALUES`, `REGISTRY-READER` and `OP-CATALOG` use accepted BASE pins; `QUERY-TRAVERSAL` coordinates one bounded fake-source health query, and `CLI-CANDIDATE-HOST`, `CLI-QUERY-ADAPTER`, `MCP-QUERY-ADAPTER` and `SLICE-PARITY` establish identical normalized request/grants/source calls/receipt/bounds/interruption. Catalog discovery has no credential, source, socket/listener or user-state effects. Candidate adapters are development-only entrypoints; public launchers and production imports remain unchanged.

The first slice does not port the whole Swift evaluator, introduce native capture, install React, relocate registry authority, connect a real device, update credentials/journals, replace distribution or admit cloud storage. Full K05/O02 requires native independent fixtures plus phone/Mac integration; O03–O07 complete workflow ports follow their bounded decomposition. C01/C02 unknown fields/versions, exact values and batch/session transitions are independent reviewed contracts, not a blanket Schema reject/ignore rule. Current native/Rust source stays the authoritative producer and compatibility comparator until profile/host-specific replacement gates. Candidate reversal leaves installed launchers, accepted settings, immutable requests, engine pins, retained spools and user outputs intact. After any later admitted migration, compatible retained engines/readers and the rollback window must preserve crash-between-commit/journal/ack, lost completion, once-only quota/commit, explicit acknowledged cancellation and downgrade paths. Missing/incompatible spool/engine reports truthful restart/pending failure; never recapture under the same immutable operation ID. Cancellation of a local Effect scope does not become durable source cancellation.

Registry/public fixture relocation, native engine/ABI adoption, host signing/credential upgrade, job writer/state migration, production authority promotion and Rust deletion each require separately claimed writes, current integrated-source evidence and independent review.
