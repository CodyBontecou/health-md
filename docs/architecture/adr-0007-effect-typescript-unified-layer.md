# ADR-0007: Effect TypeScript core, common operations and shared React

- **Status:** Selected successor architecture; implementation and host admission unqualified. Q-LOCAL technical resolution awaits independent review.
- **Date:** 2026-10-07
- **Decision owner:** Architecture; product requirements selected by the owner in D01–D18.
- **Source reviewed:** `a2d59ce49f70537ac9ca3bbdd849d6c08b4235e0`; accepted inventories retain their original `912c58553c0f692ae8667f32ec7fd7a8c6ceff8d` source pins.
- **Scope:** Local portable contracts/core/protocol, complete common operations, Node CLI/MCP, shared feature models and React, coarse native capabilities, temporary coexistence and eventual Rust retirement. Cloud deployment/product choices remain independent.
- **Predecessor:** [ADR-0001](adr-0001-shared-rust-uniffi-core.md); retained implementation authority until each replacement passes its own gates.
- **Decision evidence and D01–D18 reconciliation:** [Q-LOCAL record](../migration/effect-refactor/decisions/local-architecture.md).

Health.md will use one portable Effect 4 TypeScript layer for application behavior and complete operations, with thin Node CLI/MCP adapters and broad shared React feature interfaces. Native SDK, security and lifecycle capabilities stay in the existing signed hosts. This replaces the Rust/UniFFI end-state chosen in ADR-0001 because the owner selected complete Rust removal and broader UI/operation sharing to improve development turnaround and disk usage; no measured speed or runtime improvement is claimed by this decision.

## Implementation boundary

`packages/contracts` remains the language-neutral schema/fixture authority. The candidate `packages/healthmd-core-ts` owns explicit contracts/codecs, deterministic semantics/rendering/planning, protocol algorithms, domain models, dataset interfaces, migration policy, complete Effect operations and React-free feature models. Effect validates shape and composes typed failures, host capabilities, concurrency, interruption and resource scopes; exact algorithms/codecs preserve historical numeric lexemes and bytes. Pure transformations remain ordinary deterministic functions. Public protocols are Health.md contracts, even where Effect offers similar unstable helpers.

Portable entry points import no React/RN, Node filesystem/network/crypto, native SDK, DOM, process environment, provider/database/object/KMS or identity SDK. Each actual host composes Effect Layers outside this graph. Tests supply fake Layers across the same interface. A VM resolves one Effect and contract module identity. Component locks, commands and outputs remain independent; this ADR creates no root build framework or package manifest.

The initial portable toolchain direction is Node 24/npm and Effect 4, using the design's researched Effect 4.0.1 as an input to verification. `TOOLCHAIN-PINS` resolves exact runtime/package/test/bundle pins and compatibility before `TS-FOUNDATION` installs them. No latest alias, installed version, RN/Hermes combination or signed distribution is established here. Runtime changes require fresh contract and host evidence.

A common operation is the complete program: normalize a fixed operation, resolve explicit caller/source/destination grants and immutable scope/profile/engine identity, admit and account for work, coordinate source/capture/query or preparation, evaluate/render, journal/stream/commit/acknowledge, reconcile/resume or explicitly cancel, and return canonical safe receipts. UI, intents, automation, schedules, CLI, local API and MCP invoke that program. Adapters own syntax, caller identity, transport presentation and host/process lifecycle; they do not maintain separate evaluator, export, job or retry algorithms. Hosting the same function does not give every caller its grants.

`packages/healthmd-ui` owns compatible React components, tokens, accessibility/localization and platform projections. React Native is the phone target in existing Apple/Android projects; React/RN Web serves compatible browser, website interactive and MCP Apps interfaces; RN macOS is the preferred desktop candidate pending a bounded host spike. Feature state/actions remain outside React and call operations. Watch, widgets, Wear, intents, extensions and constrained/background hosts retain native capture/presentation or versioned snapshot projections until their specific hosting proof exists. Shared UI is a feature/state/entrypoint coverage obligation, not evidence that every surface is already ported.

Native adapters own supported SDK acquisition/authorization, source aggregation and calendar evidence, protected data, sockets/secure-channel sequence and nonce/key lifecycle, Keychain/Keystore/desktop credential facilities, background entrypoints, destination descriptors/locks/atomic commits, and app-group/extension integration. They exchange owned bounded batches, immutable configurations, exact result/artifact bytes or bounded streaming handles, explicit checkpoints and cancellation values. No per-sample callback/FFI or native object retention crosses the seam. Portable operations own business policy/state transitions; native capabilities own OS effects and crash-safe primitives. A native collector persists an inbox/checkpoint while React is suspended, then idempotent portable processing acknowledges its consumed frontier.

Node ordinary paths, rename and process startup are insufficient evidence for existing destination-race guarantees or signed credential continuity. The eventual desktop implementation needs separately qualified non-Rust native capabilities for descriptor-relative traversal, stable file identities, safe replacement, locking/durability and credential custody. The exact native implementation language/ABI and distribution mechanism remain bounded technical decisions. Rust helpers are temporary references, not the final native capability implementation.

## Contracts and the expanded product

The rewrite preserves active Apple daily v8, historical Apple profiles, Android frozen v4/analytical v5, Apple requested-range `healthmd.rollup_summary` v9, semantic/result/render/artifact v1, current registry bytes and independently versioned direct protocols. Common daily `healthmd.health_data` v9 remains a separate proposal. Preserve core API 4 and semantic-result v1's embedded historical API 3 without global substitution; renderer revision 2, persisted-state 1 and host adapter/build identities remain independent.

Exact binary64 bits/integer strings, timestamp seconds/nanoseconds, civil owner dates, SDK aggregates, missing versus zero, profile order/number lexemes, paths/hashes and NFKC/full-casefold collisions must survive. Effect Schema is not a replacement serializer. Unknown-field/enum/version policy is contract-specific. Registry relocation, generators and schema extraction are separately reviewed cutovers. Inventory discrepancies remain reconciliation work; this ADR changes no admission rule, fixture or byte contract.

P01–P03, L00–L05, S00–S06 and H00–H09 extend the common interfaces with separately versioned typed health, location and `device_usage` payloads, source identities, time/provenance/coverage and explicit domain/source/device/operation/range/detail/field/precision/title grants. `healthmd.personal_data` v1 and these domain IDs remain proposed public contracts until C14 review. Health trust is not location/usage consent. One logical dataset can use distinct physical stores and the native health source without duplicating its corpus. Observations, aggregates, annotations and inference retain the meanings in [the glossary](../../GLOSSARY.md).

Mac app/device sessions and window titles are first desktop acquisition scope; browser-title/history/input acquisition and Windows/Linux collectors remain deferred. iOS historical aggregates are the accepted labeled first-release exception, with exact iOS sessions required under S06 follow-up and no fabricated launch/close times. Donor source/history/licenses and migration archives must be pinned and reviewed before import; donor grants, entitlements, commerce or sync do not transfer automatically.

Optional cloud is another explicitly selected destination and committed-export source using the same operations. Local use requires no account and an unavailable phone never silently selects cloud. Upload, owner administration/download/deletion and agent-read grants are distinct. Source-purpose/recipient restrictions apply before spool/upload and disclosure. Initial queryable custody is server-readable, with actual regional/recovery/retention controls and named client interoperability separately qualified; it is not an E2EE claim. Region, provider/topology, billing, identity/recovery, restore/loss, retention and rollout choices stay under H00/H01 and other cloud decisions. Practice, Wake, static website, OAuth broker and pricing analytics retain their existing isolated authority; Wake is notification-only.

## Candidate slice and coexistence

The first executable slice is a development-only fake-source health query/discovery program. Accepted inventories and `TOOLCHAIN-PINS` precede `TS-FOUNDATION`; `CODEC-VALUES`, `REGISTRY-READER`, `OP-CATALOG`, `QUERY-TRAVERSAL`, `CLI-CANDIDATE-HOST`, candidate CLI/MCP adapters, `SLICE-PARITY` and portable CI provide its bounded implementation/parity evidence. Both adapters must produce identical normalized scope, grants, source calls, bounds, continuation/partial receipts and interruption. Discovery opens no source, credential, socket/listener or user state. Fake capabilities do not acquire real device/file authority.

Current public launchers, native/Rust exporters and Swift query evaluation remain production authorities. Preserve the 21-tool full and 13-tool read-only catalogs, exact command/error/guidance identities, guessed-name rejection and separate grants. Android direct typed query remains unavailable pending its native qualification; source adapters never substitute a corpus or different product. Existing phone-produced pages can later use the same portable evaluator only after native independent precision/coverage/context/evidence fixtures and integration pass. The first slice does not install React, replace complete production evaluation, relocate registry authority, migrate secrets/journals or publish a Node replacement.

Every implementation/host/profile has an explicit current authority, candidate identity, immutable fixture pins, accepted checks, persisted-state effect and rollback route. `EngineBuildInfo` binds package/source/bundle/registry/contracts/renderer identity; host-adapter ABI is separately versioned. Retained requests, profiles, journals, spools, source/peer binding, committed frontier and ack state keep their accepted engine pins. An incompatible or missing engine/spool fails with the existing bounded recovery/restart/pending semantics; no silent regeneration, re-pair, destination reroute or schema relabeling. Local waiter interruption does not imply acknowledged phone-side durable cancellation.

Revert candidate files before promotion without touching public launchers or retained/user state. Later profile/host promotion requires exact integrated-source tests, independent review, producer/consumer coverage, real supported host/distribution proof and explicit authorized action. Keep the previous compatible implementation/engine available through the recorded rollback window. Retirement needs its own reviewed change after complete required matrices and recovery/downgrade proof; preserve historical releases/Git provenance and remove all active Rust build/runtime/generation/CI/release dependencies only when replacements and clean Rust-free checkout evidence pass. This decision grants no production promotion or deletion.

## Consequences and reconsideration

Contract and operation tests can eventually run without native toolchains, while SDK/security/release integrations still require native checks. Actual cold/warm edit loops, CI time, startup/memory, one/three-worktree disk footprints and cleanup exclusions must be measured before speed/space claims. Coexistence temporarily increases maintained paths and comparator cost.

Retaining only Rust build optimizations would not meet selected complete Rust removal; replacing only the export core would not meet shared complete operations/UI scope. Those remain transitional reference techniques. This ADR changes the target architecture, not the present supported implementation or public versions.

Revisit the affected seam/pin/task if exact codecs, bounded streaming, host lifecycle, signing/credential continuity, crash/downgrade, source-purpose policy, supported runtime APIs or measured budgets fail. Preserve selected product scope and existing authority while requalifying; a failed host spike cannot silently remove a required feature or invent parity. Update applicable root/component instructions, development/operator/QA skills, architecture/build/release docs and CI path maps in the same scoped implementation/retirement change that makes their current Rust-specific rule obsolete. Independent review and coordinator acceptance of Q-LOCAL remain pending for this patch.
