# Direct protocol v1

This document specifies the deployed Health.md iPhone direct-CLI protocol. It is normative together
with [`fixtures/swift-reference.json`](fixtures/swift-reference.json). The fixture was generated by the Swift
[`HealthMdConnectionCore`](../../../../apps/apple/Packages/HealthMdConnectivity/Sources/HealthMdConnectionCore)
implementation and is asserted byte-for-byte by Rust tests.

## Roles and limits

The CLI is the TCP listener and the foreground iPhone connects to it.

| Property | Value |
|---|---:|
| Manual IP/Tailscale port | 17647 |
| Pairing/application/transfer version | 1 |
| Maximum outer JSON packet | 2 MiB |
| Binary chunk body | 512 KiB |
| Partition range | 32–64 MiB |
| Preferred partition | 48 MiB |
| Preferred in-flight window | 4 |
| Pairing-code lifetime | 10 minutes |
| Durable job lifetime | 7 days |

Every TCP packet is `u64be(json_byte_count) || JSON`. A receiver must reject zero and values above
2 MiB before allocation, then perform exact reads. This is distinct from classic Mac-app Manual IP
port 17646 and its protocol/domain constants.

## Foundation JSON compatibility

Swift synthesized associated-value enums use an object box:

```json
{"hello":{"_0":{"platform":"macos_cli"}}}
{"completionConfirmed":{"jobID":"ABCDEFAB-CDEF-4ABC-8DEF-ABCDEFABCDEF"}}
{"ping":{}}
```

Other rules:

- Swift `Data` is standard padded base64.
- Codable UUID text is uppercase and hyphenated.
- UUIDs inserted into cryptographic transcripts and file item IDs are lowercase.
- Nil optionals are absent, never `null`.
- Secure JSON and fingerprints use sorted keys, no whitespace, unescaped `/`, and UTC ISO-8601
  dates with whole-second precision.
- `DirectDateSelection` is `{"exact":{"start":"...","end":"..."}}` or
  `{"allAvailable":{}}`.
- Protocol v1 requires the portable client to advertise the legacy role string `macos_cli`.

## Pairing handshake

The iPhone sends a `pairingRequest` outer packet with protocol version 1, name, 32-byte X25519
public key, 32-byte nonce, code verifier, and installation UUID. A trusted reconnect sends an empty
`codeVerifier` and includes `trustedVerifier`. The pairing code itself is never transmitted.

The server returns `pairingResponse` with its raw X25519 public key and nonce, installation UUID,
authentication verifier, and the reconnect secret sealed in a separated ChaCha20-Poly1305 frame:

```json
{
  "nonce": "<base64 12 bytes>",
  "ciphertext": "<base64 32 bytes>",
  "tag": "<base64 16 bytes>"
}
```

Define `F(value) = u64be(byte_count) || value` and `L(uuid)` as lowercase ASCII UUID text.

```text
code_key = SHA256("HealthMd.DirectCLI.Code." || six_ascii_digits)

pairing_client_proof = HMAC-SHA256(
  code_key,
  "HealthMd.DirectCLI.PairingVerifier.v1"
  || F(L(client_id)) || F(client_public_key) || F(client_nonce)
)

trusted_client_proof = HMAC-SHA256(
  reconnect_secret,
  "HealthMd.DirectCLI.TrustedClient.v1"
  || F(L(client_id)) || F(client_public_key) || F(client_nonce)
)

session_key = SHA256(
  "HealthMd.DirectCLI.SessionKey.v1"
  || raw_x25519_shared_secret || F(client_nonce) || F(server_nonce)
)
```

For a new pairing, the server proof is:

```text
HMAC-SHA256(
  code_key,
  "HealthMd.DirectCLI.PairingServer.v1"
  || F(L(client_id)) || F(client_public_key) || F(client_nonce)
  || F(L(server_id)) || F(server_public_key) || F(server_nonce)
  || 0x01 || F(sealed.nonce) || F(sealed.ciphertext) || F(sealed.tag)
)
```

For trusted reconnect:

```text
HMAC-SHA256(
  reconnect_secret,
  "HealthMd.DirectCLI.TrustedServer.v1"
  || F(L(client_id)) || F(client_public_key) || F(client_nonce)
  || F(L(server_id)) || F(server_public_key) || F(server_nonce)
  || 0x00
)
```

The trusted response still seals the existing secret, but that frame is excluded from the trusted
server transcript. AEAD is IETF ChaCha20-Poly1305 with a fresh 12-byte nonce and empty AAD.

Trust is keyed by stable iPhone installation UUID. A code pairing rotates the 32-byte reconnect
secret; trusted reconnect preserves it. Persist trust before sending the successful response.

## Secure channel

After pairing, every outer packet must be `encrypted`. Its decrypted plaintext is:

```text
"HMDSC001" || u64be(direction_sequence) || inner_payload
```

Each direction has an independent sequence beginning at zero. Duplicate, skipped, or reordered
sequences terminate the connection. The sequence is inside ciphertext, not an AEAD nonce or AAD.
Every JSON message and binary chunk consumes one sequence number.

An inner payload beginning with `HMDDIRCT` is a binary transfer frame. Every other payload is a
canonical `DirectMessage` JSON document.

## Capabilities

A portable client advertises application version 1, platform `macos_cli`, both raw profiles,
durable jobs, canonical extraction, and transfer capabilities `[1]`, binary frame `[1]`,
32/48/64 MiB partition bounds, and four in-flight chunks. Select the highest common versions,
intersect partition bounds, clamp the larger preferred size into the intersection, and clamp the
minimum peer window to 1–8.

## Requests and fingerprints

The fingerprint is lowercase hexadecimal SHA-256 over only the canonical `DirectExportRequest`
JSON, not its enum wrapper. `createdAt` is floored to a whole Unix second before hashing. Optional
nil fields are absent. The Swift fixture pins a complete projection request and expected digest.

## Binary chunks

```text
0..7    ASCII "HMDDIRCT"
8..9    u16be frame version = 1
10..25  raw UUID bytes
26..29  u32be sequence, starting at 1 in each partition
30..33  u32be payload byte count
34..65  raw SHA-256 bytes
66..    payload, at most 512 KiB
```

The binary frame is itself encrypted and sent as an outer length-prefixed JSON `encrypted` packet.

## Transfer order and durability

```text
iPhone -> exportAccepted, progress*, transferSession, manifests*
for each globally contiguous zero-based partition:
  iPhone -> transferOpen
  CLI    -> transferDisposition(needed | already_committed | rejected)
  if needed:
    iPhone -> binary chunk
    CLI    -> transferChunkAcknowledgement
    ...
    iPhone -> transferPartitionComplete
    CLI    -> transferPartitionAcknowledgement

iPhone -> transferFinalize
CLI    -> validate/assemble/commit durably
CLI    -> transferFinalAcknowledgement
iPhone -> completionConfirmed
```

The first partition has no previous digest; every later partition names the prior partition SHA-256.
A logical day or file may cross any number of bounded partitions. Resume must reuse the exact
request, peer binding, session, manifests, transfer IDs, descriptors, and committed frontier.
Pending bytes are disposable after disconnect. `already_committed` is valid only for a byte-for-byte
matching descriptor. The CLI marks a job completed only after `completionConfirmed`.

## Platform notes

Manual IP/Tailscale is portable. Nearby is Apple MultipeerConnectivity and is not part of the Rust
client. Current iPhone destination validation expects an absolute path beginning with `/`; therefore
Windows raw extraction is compatible, while generated-file destination mode requires a v2 logical
destination contract before it can be advertised safely.
